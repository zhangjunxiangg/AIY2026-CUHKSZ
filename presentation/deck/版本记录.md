### 🐞 过程中一个静默失败（值得记）

第一次生成 v4 时第 10 页**没生效**，但脚本报「16 处改动」且断言全过。原因：提取待替换块用了
`s.index('...border-top:1px solid rgba(255,255,255,.22)...')` 从**文件开头**搜索结束边界，
而**封面页有同款标记且在第 10 页之前** → 起点 > 终点 → 切片得到空字符串 →
`s.replace('', new, 1)` 把内容插到了**文件最开头**，而 `s.count('')` 恒 ≥1 所以断言毫无察觉。

**教训**：① 块提取一律先限定到目标 `<section>` 范围内再 index ② 断言必须包含 `assert old`（非空）
和内容特征（`'上台前复核' in old`）+ 长度区间，不能只断言 `count>=1`。

**验收**：Playwright 逐页 1920×1080——10/10 页无溢出、无隐藏元素、无断图、无页面错误；
残留检查 `上台前复核=0` / `产品图引用=1`。PDF 每页仍为动画播完的静态态。

## v3 · 2026-08-06 01:3x · 动画版

**改动来源**：用户要求把 `dist-single.html` 的动态效果用进路演 deck。**两手准备：HTML 带动画、PDF 每页静态。**

### ⚠️ 先更正一条判断

v1/v2 我基于 `docs/exp-guizang-ppt-skill-swiss-style-pitfalls.md`（8/2 写的）刻意不用 `data-anim`，理由是"recipe 结构不匹配会让整页停在 opacity:0 变全白"。**读 `base.html` 源码后发现这个坑在当前模板里已被修掉**（base.html:2929–2943）：

```js
/* 关键:[data-anim] 容器很多时候只是占位标记... 默认强制 reveal 所有 [data-anim] 容器 */
slide.querySelectorAll('[data-anim]').forEach(el=>{ el.style.opacity='1'; el.style.transform='none'; });
const fn = RECIPES[recipe];
if(fn){ fn(slide, all); return; }
if(all.length) animate(all, {opacity:[0,1], y:[12,0]}, ...);   // recipe 名不认识 → 通用 fade
```

**先无条件把元素设为可见，才调 recipe**；recipe 名不认识还有通用 fade 兜底。最坏情况是"没动画"，不是"全白"。**v1/v2 当时过度保守。**

### 自动连播：不存在

`go()` 的**全部**调用点都是用户输入——导航点击(2131) / 索引卡(2177) / 方向键(2198,2201) / 滚轮(2210) / 触摸滑动(2221) / 初始化一次(2227)。**没有 `setInterval`，没有自动翻页。** 三个概念要分开：
- **自动翻页** = 不存在，100% 靠按键
- **入场动画** = 翻到某页后自动播一次，播完停在最终态，不循环
- **ASCII 呼吸场** = 持续缓慢流动（第 10 页氛围，用户明确要）

### 安全网（三层 + 一个逃生舱）

1. 模板自带的强制 reveal（上面那段源码）

**修掉两个 bug（v2 就有，v2 未修，见下方 v2 已知缺陷）**：
1. 🐞 **ESC 监听器泄漏**：注册用捕获阶段 `addEventListener(..., true)`，移除时漏传第三个参数 → `removeEventListener` 匹配不上 → 监听器残留 → **此后每次按 ESC 都被拦，索引页再也打不开**
2. 🐞 **视频不自动播**：`v.autoplay = true` 被浏览器自动播放策略拦掉。改为 `loadeddata` 后显式 `v.play()`（点击是用户手势，所以允许带声音）；失败则显示「按 ▶ 开始播放」提示兜底

**上台注意**：
- 编码必须 **H.264 + AAC + MP4**（剪映默认导出就是）。HEVC/H.265 Chrome 播不了
- **单文件版不能内联视频**——90s 1080p mp4 约 20–50MB，base64 后膨胀 33%，浏览器解析会卡。视频一律外挂，所以「单文件 HTML + 2 个 mp4」要一起拷
- 大文件首次点击可能缓冲几秒，**上台前先点一次预热**（浏览器会缓存）

### 🔧 v3 修订 1 · 2026-08-06 02:2x —— 视频层「进去出不来」

**现场反馈**：进到视频里就回不来了。**这是我的设计缺陷，不是操作问题。** 三个原因叠加：

1. video 元素 `width:100%;height:100%` **铺满整个遮罩层** → 「点空白关闭」的判断 `ev.target === wrap` 几乎永远不成立 → **点哪都关不掉**
2. mp4 不存在时用 `wrap.innerHTML = ...` 把内容整个替换，提示 div 同样铺满 → 也点不掉。**而视频还没做出来，用户撞上的正是这个分支**
3. 没有可见的关闭按钮，唯一出路 ESC 只写在一行 16px / 透明度 60% 的小字里

**修复——四条冗余退出路径**：
- 右上角常驻 **`✕ 关闭 (ESC)`** 按钮（z-index 最高，任何分支都不会被覆盖）
- 点视频画面**四周的黑边**（video 改 `max-width/max-height + width:auto`，盒子贴合画面，黑边归 stage）
- **ESC / Backspace / Q** 三个键
- 关闭前先 `document.exitFullscreen()` —— 否则进过原生全屏后第一次 ESC 会被浏览器吃掉
- mp4 不存在时只替换舞台内容，**关闭按钮始终在**，提示字号 16→18/24px 并写明三种退出方式

**验收**：5 条退出路径 × 2 种场景（mp4 不存在 / 存在）= **10/10 全部成功退出并干净回到第 3 页**。
> ⚠️ 第一版测试脚本判据写错了（`[style*="z-index:9999"]` 匹配不到 DOM 规范化后的 `z-index: 9999`，带空格），"通过"是假的。改用「关闭按钮是否存在」作判据后重测才可信。

> **v1 / v2 未修**（保留原样供回溯），它们的视频层有同样的缺陷 + ESC 监听器泄漏。**要用视频一律用 v3。**

### PDF 保持静态

截图前每页等 **3200ms**（远超最长动画 ≈1.7s），并在截图前断言"无元素 opacity<0.99"。所以 v3 PDF 每页都是动画播完的最终静态态，和 v2 PDF 观感一致。

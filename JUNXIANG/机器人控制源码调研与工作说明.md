## 0. 先说结论

官方源码包已经提供了机器人最难替代的底层能力：底盘驱动、机械臂和夹爪接口、IK、雷达、Astra/Gemini 335 接入、SLAM/导航配置、标定工具、健康检查和 M-Claw 安全操作脚本。

官方**没有**提供一套可以直接参赛的完整任务程序。我的工作不是重写驱动，而是在这些能力上补齐：

```text
接收结构化任务/目标
  → 启动前检查
  → 安全移动或导航
  → 视觉对准与坐标校验
  → IK 可达性检查
  → 抓取、抬升、运输、放置
  → 全程超时、急停和失败恢复
  → 返回可解释的成功/失败结果
```

当前已经具备开始“离线控制骨架”开发的条件，但还不具备把完整任务接口写死的条件，原因有两个：

1. 仓库中尚未出现最终选题/场景定稿；现有资料仍是“实验室巡检”和“开放词汇寻物”两个候选方向。
2. 仓库中尚无张宇辰维护的《接口约定.md》，C→D 的目标格式、E→D 的任务格式、D→上层的状态格式还没有成为团队唯一标准。

因此，第一批代码应只做**与场景无关的控制、安全、状态机和模拟测试**；最终 ROS 话题名与任务字段必须等接口约定落盘后接入。

## 1. 官方任务与我的责任

### 1.1 比赛要求的完整闭环

官方要求作品形成下面这条可观察链路：

```text
用户指令或环境事件
  → M-Claw 参与理解或规划
  → 多设备协同
  → 机器人产生可观察动作
  → 系统反馈结果
```

与机器人控制最相关的官方任务方向是：

- 巡检：按照路线经过指定点位，识别异常并返回结果。
- 搜索与目标定位：寻找立牌、标签或物体，返回位置和识别结果。
- 搬运与分类：识别目标，完成接近、抓取、运输和投放。

我的动作段直接影响：

- 原型完成度与演示效果 20 分；
- 安全性与可扩展性 10 分；
- 系统闭环 10 分中的动作和状态反馈部分；
- 演示素材中最直观的“机器人真的完成任务”。

### 1.2 我的工作输入、处理和输出

```text
输入
├─ C（应露）：目标类别、目标位置、坐标系、置信度、时间戳
└─ E（山茶）：已经拆好的结构化任务或动作序列

我的处理
├─ 检查目标是否新鲜、坐标系是否正确
├─ 选择移动/导航/对准/抓取/放置动作
├─ 调用已有 Topic、Service 和 Action
├─ 监控雷达、舵机反馈、IK、超时与取消
└─ 失败时停车并进入安全状态

输出
├─ 当前任务阶段
├─ 成功或失败
├─ 失败码和可读原因
└─ 可用于软总线、界面和 M-Claw 汇报的状态
```

### 1.3 明确不属于我的工作

- 不负责理解自然语言或让 LLM 决定底层速度；这是 E 的任务规划职责。
- 不负责定义全队共享消息格式；由 A（张宇辰）维护《接口约定.md》。
- 不负责重写 STM32、电机、雷达、相机或舵机驱动。
- 不直接访问串口，不调用 `/ros_robot_controller/set_motor`。
- 不发送或轮询 `motor_type`。
- 不负责两块板的烧录、网络、自启基础设施；这部分由 B 主责，我提供运行入口和参数。
- 不把相机坐标直接当 `base_link` 抓取坐标。

## 2. `source code` 到底是什么

它可以理解为“厂家 SDK + 当前 4.1 适配源码 + 历史 ROS 参考工程”，不是一个开箱即用的比赛应用。

### 2.1 源码可信度分层

| 优先级 | 目录 | 定位 | 使用方式 |
|---|---|---|---|
| P0 | `source code/kaihong_adapter/mclaw-skill/` | 当前 4.1 统一安全操作入口 | 安全限制和底层调用写法的首要参考 |
| P0 | `source code/kaihong_adapter/robot-runtime/` | 板端 `/data/robot-host/` 的运行适配源码 | 查询当前宿主 ROS、启动链、Topic/Service/Action |
| P0 | `robot-runtime/student/` | 官方参赛者入口 | 复用场景模板、校验器、标定工具和感知示例 |
| P1 | `robot-runtime/navigation_runtime/` | 当前宿主 SLAM、AMCL、move_base 配置 | 地图和定位验证通过后使用 |
| P2 | `source code/ros_ws/src/` | 完整 ROS1 工作区和历史示例 | 学习算法与状态流程，不直接照搬接口和参数 |
| P3 | `ros_ws/src/third_party/` | 雷达、相机、导航等第三方依赖 | 原则上不修改 |

所有本地源码仍需与现场 `/data/robot-host/` 做版本核对；“本地源码已确认”不等于“现场板一定同版本”。

### 2.2 当前 4.1 运行架构

```text
小车板宿主 ROS
├─ roscore / ROS Master
├─ ros_robot_controller       控制板、IMU、电量、舵机底层
├─ chassis_controller         /cmd_vel → 四轮速度
├─ cmd_vel_odom_node          指令积分生成 /odom（开环）
├─ lidar                      发布 /scan
├─ host_arm                   舵机状态、机械臂控制、IK、动作组
└─ navigation_runtime         gmapping / AMCL / move_base

rk3588s-vision Docker
├─ Astra RGB-D
├─ 视觉检测
└─ 辅助目标 relay

辅助板
└─ Gemini 335 驱动与本地视觉处理
       ↓ ROS 网络
小车板 ROS Master
```

`start-all-4.1.sh` 的启动顺序是：宿主底盘 → 雷达 → 机械臂 → Astra 视觉。任一关键层启动失败会回滚已经启动的部分。

## 3. 已从当前源码确认的能力

### 3.1 底盘

| 能力 | 接口/事实 | 开发含义 |
|---|---|---|
| 全向速度 | `/cmd_vel`，`geometry_msgs/Twist` | `linear.x/y` 和 `angular.z` 控制麦轮 |
| 硬限制 | 平面合速度 ≤0.20 m/s，角速度 ≤0.50 rad/s | 上层还应设置更低的演示限速 |
| 有界命令 | 单次 0.1–10 s，官方脚本以 20 Hz 发布 | 动作结束必须持续发零速 |
| 驱动看门狗 | 0.5 s 没有新指令自动输出四轮零速 | 是最后兜底，不替代主动停车 |
| 底层转换 | 当前 `chassis_controller` 已处理麦轮运动学 | 我不需要重写轮速公式 |

### 3.2 里程计与导航

| 能力 | 接口/事实 | 开发含义 |
|---|---|---|
| 里程计 | `/odom`，30 Hz | 由 `/cmd_vel` 积分，不是真实轮编码器反馈 |
| SLAM | gmapping + `/scan` + `/odom` | 源码存在，不代表现场地图已经可用 |
| 定位 | AMCL，`odom_model_type=omni` | 需要真实地图、正确雷达位姿和初始定位 |
| 导航 | `/move_base`，DWA 支持全向底盘 | 启用前必须验证地图、TF、AMCL 和恢复行为 |
| 默认导航限速 | 平移 0.12 m/s、旋转 0.35 rad/s | 低于厂家硬限制，但仍需现场确认 |

结论：导航栈不是“没有”，但也不能把 `goto_point()` 当成已经可靠。第一版优先做短距离有界移动和视觉对准；地图导航作为地图与 AMCL 验收后的能力开关。

### 3.3 机械臂、夹爪和 IK

| 能力 | 接口/事实 | 开发含义 |
|---|---|---|
| 舵机反馈 | `/servo_controllers/port_id_1/servo_states` | 可检查 ID、当前值、目标值、误差和电压 |
| 单舵机命令 | `/servo_controllers/port_id_1/id_pos_dur`，`RawIdPosDur` | ID1–5；动作前后都要读反馈 |
| 夹爪 | ID10，官方操作范围 250–800 | 实际开合方向和夹取值要实测 |
| 安全增量 | >120 需确认净空；>250 拒绝 | 大动作必须拆成小步或用已验证动作序列 |
| IK | `/kinematics/set_pose_target` | 输入 `base_link` 下 XYZ、pitch 和扫描范围 |
| IK 输出 | `success`、5 路 pulse、current_pulse、rpy | IK 只求解，不代表已经执行或无碰撞 |

IK 成功后仍要做：脉冲范围检查、相对当前值的增量检查、执行、等待、反馈误差检查。

### 3.4 动作组

- 当前 `ActionGroupRunner` 默认从 `/data/robot/ActionGroups` 读取动作文件。
- 当前源码注释和实现使用 **JSON**，不是现有个人文档里写的 `.dpg`。
- 本地源码包没有附带任何可直接使用的动作组文件，必须在现场板上列目录确认。
- 动作组会同时下发多个关节，执行器本身没有复用 M-Claw 的“单关节增量”安全检查。

结论：只有确认文件内容、起始姿态、最大增量和净空后，才能把某个现成动作组加入白名单；不能因为“文件存在”就直接运行。

### 3.5 雷达与安全

- `/scan` 提供 `sensor_msgs/LaserScan`。
- 官方 `scan-sector-report.py` 已示范过滤非有限值、量程外数据，并按扇区计算最小值、P10 和中位数。
- 单独发布一次零速不是可靠的独立急停：如果另一个节点仍以 20 Hz 发布非零 `/cmd_vel`，底盘可能立即重新运动。

因此推荐的安全结构是：

```text
动作节点 / move_base
       ↓ 速度请求（不直接发 /cmd_vel）
唯一安全门控节点
├─ 检查速度硬限制
├─ 检查雷达方向扇区
├─ 检查雷达新鲜度
├─ 检查急停锁存状态
└─ 最终唯一发布 /cmd_vel
```

导航启动时也要把 move_base 的速度输出重映射到安全门控输入，不能让它绕开安全节点直发 `/cmd_vel`。具体内部话题名需由 A 写进《接口约定.md》。

### 3.6 相机、目标接口和标定

- Astra 运行在 `rk3588s-vision` 容器，提供 RGB、深度和相机内参。
- Gemini 335 运行在辅助板，更推荐在辅助板本地完成视觉识别，只向小车发布小数据结果。
- 源码已有候选 C→D 接口：
  - `/competition/aux_target`：`geometry_msgs/PointStamped`，`frame_id=base_link`；
  - `/competition/aux_target_valid`：目标是否有效；
  - `/competition/aux_target_json`：带元数据的 JSON。
- relay 会检查目标文件年龄、XYZ 范围和 Z 范围，默认超过 5 s 视为过期。

这套接口非常适合提交给张宇辰作为《接口约定.md》的候选，而不是重新发明目标坐标话题。

抓取前必须完成对应标定：

| 使用场景 | 必须使用的标定 |
|---|---|
| Astra 目标 → 机械臂抓取 | Astra→`base_link` 手眼标定 |
| 辅助相机目标 → 地面移动 | 辅助相机→`competition_ground` |
| 辅助相机目标 → 机械臂抓取 | 辅助相机→`base_link` 手眼标定 |

地面标定不能替代机械臂手眼标定。相机或支架位置、角度、分辨率变化后，对应外参失效。

### 4.2 只能参考流程，不能照搬

`ros_ws/src/competition/scripts/navigation_transport/automatic_pick.py` 属于旧 ROS 示例，存在以下差异：

- 使用 `/robot_1/controller/cmd_vel`，当前 4.1 权威接口是 `/cmd_vel`；
- 使用 `/robot_1/.../multi_id_pos_dur` 同时下发多关节；
- 角速度上限写到 1.2 rad/s，超过当前 0.50 rad/s 硬限制；
- 写死多组舵机脉冲，没有当前实车反馈与标定保护；
- 依赖旧 Gemini 话题和旧参数命名。

可以借它的只有：目标检测 → PID 对准 → 稳定判断 → 停止 → 进入下一阶段的状态流程。

## 5. 我的实际交付物

### 5.1 控制原语层

向动作层提供统一、可测试的基础能力：

- `health_check()`：确认 ROS Master、底盘订阅者、雷达、机械臂和标定文件。
- `move_bounded()`：有界速度和时间，动作结束主动停车。
- `stop_chassis()`：持续发布零速并确认控制链存在。
- `read_arm()`：读取并验证 ID1–5 和 ID10 的稳定反馈。
- `move_joint_safe()`：单 ID、增量保护、执行后反馈验收。
- `set_gripper_safe()`：夹爪范围、实测开合值、执行后反馈。
- `solve_ik()`：检查目标坐标系、扫描 pitch、选择安全解，不直接执行。
- `execute_ik_solution()`：把 IK 解拆成经过增量检查的动作。

### 5.2 唯一安全门控

- 所有自动速度请求必须经过安全门控。
- 雷达无数据、数据过期、急停锁存、速度超限时一律输出零速。
- 根据速度方向选择前/后/左/右对应雷达扇区，而不是只看全局最小值。
- 急停后默认锁存，需要明确复位，不因障碍物短暂消失自动恢复。
- 节点退出、异常或取消时持续发布零速。

### 5.3 组合动作状态机

推荐状态：

```text
IDLE
  → PRECHECK
  → NAVIGATING 或 APPROACHING
  → ALIGNING
  → TARGET_RECHECK
  → IK_CHECK
  → PREGRASP
  → GRASPING
  → GRASP_VERIFY
  → LIFTING
  → TRANSPORTING
  → PLACING
  → RETURNING（按场景可选）
  → SUCCEEDED

任意状态
  → STOPPING
  → FAILED / CANCELLED / ESTOPPED
```

每个状态都必须有：进入条件、成功条件、超时、取消、失败码和安全退出动作。

### 5.4 对外控制节点

- 接收 A 定义的结构化任务，而不是自然语言。
- 接收 C 的目标数据，并检查 `frame_id`、时间戳、valid 和置信度。
- 串行动作，拒绝同时执行多个会动机器人的任务。
- 发布任务阶段、成功/失败、失败码和可读信息。
- 支持取消，取消必须先停车，再处理机械臂安全位。

建议提交给 A 的任务字段草案：

```text
task_id
action                 NAVIGATE / PICK / PLACE / PICK_AND_PLACE / STOP
target_id
source_location
destination_location
timeout_s
```

建议状态字段草案：

```text
task_id
state
success
error_code
detail
timestamp
```

以上只是供《接口约定.md》采用的候选，不是我单方面确定的团队接口。

### 5.5 测试、记录和演示保障

- Mac 上的假后端和单元测试，不依赖 `rospy` 也能验证状态机和安全规则。
- 板上只读 smoke test：健康、话题、服务、动作服务器、参数和标定文件。
- 单动作验收记录：输入、预期、真实反馈、耗时、结果和失败原因。
- 实测参数配置：抓取姿态、夹爪值、对准方向、速度、阈值和超时。
- 路演操作小抄和降级方案：完整链、单动作、视频三档。

## 7. 开发顺序与门禁

### 阶段 A：无板也能完成

1. 建 ROS 包骨架和 README。
2. 建纯 Python 数据模型、错误码和硬安全限制。
3. 建 fake backend，确保本地测试绝不发布真实 ROS 指令。
4. 实现控制原语的校验逻辑和自动停车语义。
5. 实现安全门控的纯算法和急停锁存。
6. 实现与具体场景无关的动作状态机。
7. 编写单元测试和模拟完整任务演示。

### 阶段 B：拿到板后的只读核验

1. 确认 HDC、板端源码版本和 `run python3 --version`。
2. 运行整机健康检查，列出 Topic、Service 和 Action。
3. 确认 `/cmd_vel`、`/odom`、`/scan`、机械臂反馈和 IK。
4. 列出 `/data/robot/ActionGroups`，检查 JSON 内容，不运行。
5. 确认已有地图、TF、AMCL、move_base 和导航状态。
6. 确认 Astra/Gemini 335 数据与三项标定状态。

### 阶段 C：用户看着机器人并明确说“走”后

1. 先状态检查，再以 0.1 m/s、2 s 做首次最小底盘动作。
2. 逐个验证前后、横移、旋转和停车；每次只发一个动作。
3. 先 `arm-read`，再用小增量验证单个舵机；第一次动起来录屏。
4. 验证夹爪方向、范围、负载和反馈。
5. 测 odom 漂移、底盘方向符号和修正系数。
6. 回填实测配置后，才允许组合动作。

### 阶段 D：标定、抓取和导航

1. 与 C 配合完成实际使用相机对应的标定并验收误差。
2. 目标静止时做视觉对准，不夹取。
3. 只问 IK，不执行。
4. 空夹爪执行安全抓取轨迹。
5. 单物体抓取、抬升、原地放回。
6. 短距离运输和投放。
7. 地图、AMCL 和安全门控通过后再开启 move_base 导航。

### 阶段 E：团队联调与封版

1. 用模拟 C/E 输入串通控制节点。
2. 替换为真实目标和任务接口。
3. 验证成功、目标丢失、IK 失败、雷达急停、取消和节点崩溃。
4. 完整链稳定后交给 B 做自启。
5. H28 后不加功能，只修成功率和演示恢复路径。

## 8. 验收标准

| 模块 | 最低通过标准 |
|---|---|
| 健康检查 | 任一关键 Topic/Service/Action 缺失时拒绝运动，并给出明确原因 |
| 底盘原语 | 速度/时长越界拒绝；完成、异常、取消时都主动发零速 |
| 安全门控 | 障碍、雷达过期、急停锁存时持续压制非零速度 |
| 机械臂 | 动前读反馈；超增量拒绝；动后误差超限视为失败 |
| IK | 非 `base_link` 或无标定目标拒绝；无解不动臂 |
| 目标输入 | 过期、invalid、坐标系错误、置信度不足时不执行 |
| 抓取 | 单物体连续多次成功；失败能回安全状态，不拖着物体继续跑 |
| 导航 | 地图、TF、AMCL、move_base 和安全门控全部通过后才启用 |
| 任务节点 | 同时只执行一个运动任务；支持取消；状态和失败码完整 |
| 演示 | 完整链、单动作降级和视频兜底均准备完成 |

具体成功率次数、急停距离、目标置信度和演示限速必须根据现场场景实测确定，不能在源码中臆测。

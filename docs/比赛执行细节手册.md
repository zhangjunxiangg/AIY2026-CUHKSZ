## 一、任务入口与 Trigger 设计

### 1.1 M-Claw 指令入口

**设计**：任务入口统一走 M-Claw，用户自然语言指令 → M-Claw 解析 → 任务队列。

**已知缺陷与 Feature Fixing**：

| 缺陷 | 影响 | 处理方案 |
|---|---|---|
| Tab 补全问题 | 输入效率低 | 向 M-Claw 工程师提 Issue；现场用预定义指令模板 |
| 长指令理解偏差 | 任务拆解错误 | 指令确认机制（见 1.2） |
| 网络依赖 | 断网无法工作 | 本地降级模式（见 5.4） |

**Issue 提交清单**：
- [ ] Tab 补全失效（具体版本号 + 复现步骤）
- [ ] 长文本指令截断问题
- [ ] 语音输入误触发

### 1.2 指令确认机制

**问题**：M-Claw 可能理解错用户意图。

**方案**：二次确认 + 状态回显。

```
用户: "把红色方块搬到A点"
M-Claw 解析: {action: "move", target: "red_block", destination: "point_A"}
系统回显: "我将执行：抓取红色方块 → 移动到A点 → 放下。确认吗？"
用户确认后执行
```

**实现**：
```python
def on_mclaw_command(cmd):
    parsed = parse_command(cmd)
    display_confirmation(parsed)  # 显示解析结果
    if wait_for_confirmation(timeout=5.0):
        execute_task(parsed)
    else:
        report_to_mclaw("任务取消")
```

## 二、位置标定与坐标系

### 2.1 两种方案对比

| 方案 | 原理 | 优点 | 缺点 | 适用场景 |
|---|---|---|---|---|
| **方案 A：自标定** | 机器人用 Astra 相机拍周围环境，匹配预设特征点 | 无需额外设备 | 初始位置未知时难启动；遮挡影响大 | 场地特征明显、光线稳定 |
| **方案 B：Gemini 335 全场标定** | 辅助相机架在场地边，俯拍全场，实时追踪机器人位置 | 全局视角，绝对坐标 | 需额外架设；网络延迟 | 比赛演示（推荐） |

**推荐**：方案 B 为主，方案 A 为备份。

### 2.2 方案 B 实现细节

**硬件布置**：
- Gemini 335 架设在场地边缘，高度 1.5-2m，俯拍全场
- 辅助板（第二块 3588S）连接 Gemini，运行视觉处理
- 通过 WiFi 将机器人位置发给主板

**坐标系定义**：
```
场地原点：左下角（0, 0）
X 轴：向右为正
Y 轴：向前为正
Z 轴：向上为正（单位：米）
```

**数据流**：
```
Gemini 335 → 辅助板（检测机器人位置）→ WiFi → 主板（/robot_pose 话题）→ M-Claw
```

**标定步骤**：
1. 演示前 30 分钟：架设 Gemini，运行 `aux-ground-calibration.py`
2. 在场地四个角放置已知标定物，记录像素坐标 ↔ 实际坐标映射
3. 验证：遥控机器人到已知点位，检查视觉定位误差 < 5cm

### 2.3 标定漂移应对

| 风险 | 检测 | 恢复 |
|---|---|---|
| 相机被碰 | 图像特征点突变 | 重新标定 |
| 光线变化 | 图像亮度/对比度异常 | 切换到低光模式 / 补光灯 |
| 网络延迟 | 位置数据时间戳过期 | 本地里程计暂代 |

## 三、任务拆解与动作序列

### 3.1 通用任务流程

```
M-Claw 指令
    ↓
任务解析（LLM 拆解为子任务）
    ↓
┌─────────────────────────────────────────┐
│  子任务 1：确定目标位置                    │
│  子任务 2：规划路径并躲避障碍              │
│  子任务 3：识别目标物体/符号               │
│  子任务 4：执行动作（抓取/读取/报告）        │
│  子任务 5：回归出发点                      │
└─────────────────────────────────────────┘
    ↓
状态反馈给 M-Claw
```

### 3.2 动作原语定义

| 原语 | 输入 | 输出 | 说明 |
|---|---|---|---|
| `move_to(x, y)` | 目标坐标 | 到达/失败 | 底盘导航 |
| `grasp_object(id)` | 物体 ID | 成功/失败 | 机械臂抓取 |
| `release_object()` | 无 | 成功/失败 | 夹爪释放 |
| `read_symbol(location)` | 位置 | 符号内容 | 视觉识别 |
| `report_status(msg)` | 消息 | 已发送 | 反馈 M-Claw |
| `return_home()` | 无 | 到达/失败 | 回归原点 |

### 3.3 场景-specific 流程

**场景 A：搬运分类**
```
1. move_to(方块区)
2. read_symbol(方块颜色)  # 或颜色识别
3. grasp_object(目标方块)
4. move_to(投放区)
5. release_object()
6. report_status("已完成搬运")
```

**场景 B：巡检报告**
```
1. for each 巡检点 in 巡检列表:
2.   move_to(巡检点)
3.   read_symbol(巡检内容)  # 识别符号/障碍
4.   report_status(巡检结果)
5. return_home()
```

**场景 C：目标搜寻**
```
1. move_to(搜索区入口)
2. spiral_search()  # 螺旋搜索
3. if found_target:
4.   grasp_object(目标)
5.   return_home()
6. else:
7.   report_status("未找到目标")
```

## 四、核心算法与算力分配

### 4.1 算法清单与部署位置

| 算法 | 功能 | 部署位置 | 频率 | 算力需求 | 备选方案 |
|---|---|---|---|---|---|
| 目标检测 | 识别方块/立牌/符号 | 辅助板 NPU | 5-10 Hz | YOLOv8n-RKNN | CPU 降分辨率 |
| 深度估计 | 获取物体距离 | 主板 CPU | 30 Hz | Astra 原生 | 无需额外算法 |
| 点云处理 | 障碍物检测 | 主板 CPU | 5-10 Hz | PCL 体素滤波 | 2D 雷达替代 |
| 路径规划 | 导航避障 | 主板 CPU | 1-5 Hz | A* / DWA | 预编程路径 |
| 抓取规划 | 抓取姿态生成 | 主板 CPU | 0.5-2 Hz | GPG / 几何启发式 | 预编程抓取位 |
| 手眼标定 | 相机-机械臂坐标转换 | 主板 CPU | 一次性 | 预计算矩阵 | 固定外参 |
| 语音识别 | 语音指令 | 云端 API | 按需 | Kimi/Qwen | 触控屏输入 |
| LLM 任务规划 | 任务拆解 | 云端 API | 按需 | Kimi/Qwen | 预定义任务模板 |

### 4.2 算力分配策略

```
主板（机器人）：
├── CPU 小核（A55）：ROS 节点、传感器数据采集、实时控制
├── CPU 大核（A76）：路径规划、点云处理、抓取规划
├── NPU：目标检测（YOLOv8n）
└── GPU：保留（OpenCL 未验证）

辅助板：
├── CPU：Gemini 驱动、图像压缩
├── NPU：视觉检测（机器人定位、目标识别）
└── 网络：结果回传主板

云端：
├── Kimi API：LLM 任务规划、语音理解
└── 备用：本地规则引擎（断网时）
```

## 五、失败恢复与容错机制

### 5.1 失败场景与对策

| 失败场景 | 检测方式 | 恢复策略 | 降级方案 |
|---|---|---|---|
| 抓取失败 | 夹爪电流/位置反馈 | 重试 2 次 → 调整位置再试 → 报告失败 | 跳过该物体，继续下一个 |
| 导航卡住 | 里程计长时间不动 | 后退 → 转向 → 重试 | 请求人工干预 |
| 识别失败 | 置信度低于阈值 | 改变视角再试 → 切换算法 | 报告"无法识别" |
| M-Claw 断连 | 心跳超时 | 本地模式运行 | 完成当前任务后停止 |
| 相机遮挡 | 图像全黑/全白 | 报警 → 等待 | 切换备用传感器 |
| 网络延迟 | 位置数据超时 | 本地里程计暂代 | 减速运行 |

### 5.2 重试机制实现

```python
def execute_with_retry(action, max_retries=2, timeout=10.0):
    for attempt in range(max_retries + 1):
        try:
            result = action(timeout=timeout)
            if result.success:
                return result
            else:
                log_failure(result.error)
        except Timeout:
            log_timeout()
        
        if attempt < max_retries:
            report_to_mclaw(f"第{attempt+1}次失败，准备重试")
            time.sleep(1.0)  # 间隔 1 秒
    
    report_to_mclaw(f"重试{max_retries}次后仍失败，放弃")
    return FailureResult()
```

### 5.3 安全回退状态

任何失败发生时，机器人应回到**安全回退状态**：
- 底盘：停止（零速）
- 机械臂：回到预设安全姿态（直立，不遮挡相机）
- 夹爪：打开（避免夹住不放）
- 报告：向 M-Claw 发送失败原因

### 5.4 本地降级模式

**触发条件**：网络断连 / M-Claw 无响应 / 云端 API 超时

**本地模式功能**：
- 预编程动作序列（如：前进 → 抓取 → 后退 → 放下）
- 固定路线巡检
- 基础避障（雷达阈值触发停止）

**切换逻辑**：
```python
if not check_network() or not mclaw_heartbeat():
    enter_local_mode()
    execute_preprogrammed_task()
else:
    enter_normal_mode()
```

## 六、安全边界与紧急停止

### 6.1 安全边界

| 边界类型 | 限制值 | 检测方式 | 响应 |
|---|---|---|---|
| 底盘速度 | ≤ 0.15 m/s | 软件限速 | 超速自动截断 |
| 机械臂工作空间 | 半径 0.4m 球体 | 关节角度限位 | 限位停止 |
| 夹爪力度 | 无压力传感器，时间限制 | 抓取超时 3s | 超时松开 |
| 工作区域 | 场地边界虚拟围栏 | 视觉/里程计 | 边界前停止 |
| 电池电压 | < 10.5V 报警 | 电压监控 | 低电回充/停止 |

### 6.2 紧急停止

**物理急停**：机器人本体红色急停按钮（如有）

**软件急停**：
```python
# 订阅急停话题
rospy.Subscriber('/emergency_stop', Bool, emergency_callback)

def emergency_callback(msg):
    if msg.data:
        # 立即停止所有运动
        pub_cmd_vel.publish(Twist())  # 零速
        release_gripper()  # 松开夹爪
        disable_torque()  # 机械臂卸力
        report_emergency()
```

**触发条件**：
- 检测到人体过于接近（< 0.5m）
- 电池电压过低
- 机械臂电流异常（碰撞）
- 用户通过触控屏/语音/遥控器触发

## 七、传感器噪声与校准漂移

### 7.1 传感器噪声处理

| 传感器 | 噪声类型 | 滤波方法 |
|---|---|---|
| Astra 深度 | 空洞、飞点 | 中值滤波 + 深度补偿 |
| 雷达 | 偶发噪点 | 滑动窗口平均 |
| IMU | 零漂 | 静止时自动校准 |
| 里程计 | 累积误差 | 视觉重定位校正 |

### 7.2 校准漂移应对

**演示前校准清单**：
- [ ] 相机内参检查（`rostopic echo /astra_camera/rgb/camera_info`）
- [ ] 手眼标定验证（抓取已知位置物体测试）
- [ ] 场地坐标系标定（Gemini 全场标定）
- [ ] 舵机零点检查（机械臂回零）

**演示中漂移检测**：
- 每 5 分钟检查一次特征点位置
- 抓取成功率下降时触发重新校准

## 八、通信架构与状态闭环

### 8.1 通信链路

```
用户语音/文字
    ↓
M-Claw（云端/本地）
    ↓ HTTP/WebSocket
任务解析器（主板）
    ↓ ROS Topic
动作执行器（主板）
    ↓ 串口
STM32（底盘/机械臂/夹爪）
    ↑ 状态反馈
ROS Topic（/task_status）
    ↑
M-Claw 确认/下一步指令
```

### 8.2 状态回报机制

**关键原则**：每一步执行完都要回传状态，M-Claw 知道"做到哪一步"。

```python
# 状态消息定义
class TaskStatus:
    task_id: str
    step: str  # "navigating", "grasping", "releasing", "completed", "failed"
    progress: float  # 0.0 - 1.0
    message: str
    timestamp: float

# 发布状态
pub_status.publish(TaskStatus(
    task_id="task_001",
    step="grasping",
    progress=0.5,
    message="正在抓取红色方块",
    timestamp=time.time()
))
```

### 8.3 M-Claw 集成点

| 功能 | M-Claw 命令 | 系统响应 |
|---|---|---|
| 任务下发 | `执行任务：搬运红色方块到A点` | 解析 → 确认 → 执行 |
| 状态查询 | `现在进行到哪一步了？` | 返回当前 TaskStatus |
| 任务取消 | `停止当前任务` | 安全回退 → 确认取消 |
| 结果报告 | 自动触发 | 任务完成/失败时推送 |

## 十二、演示脚本与降级方案

```
1. 开场（30s）：介绍场景和机器人
2. 任务下发（30s）：语音/文字指令给 M-Claw
3. 任务执行（2-3min）：
   - 机器人自主导航到目标区
   - 识别并抓取目标物体
   - 搬运到指定位置
   - 返回出发点
4. 结果确认（30s）：M-Claw 报告任务完成
5. 收尾（30s）：总结亮点和技术架构
```

### 12.2 降级方案

| 级别 | 条件 | 方案 |
|---|---|---|
| 真跑 | 一切正常 | 完整流程现场演示 |
| 模拟 | 网络/传感器部分故障 | 脚本造数据 + 预录视频辅助 |
| 兜底 | 硬件严重故障 | 演示视频 + 设计思路讲解 |

### 12.3 风险预案

| 风险 | 概率 | 应对 |
|---|---|---|
| 网络断连 | 中 | 本地降级模式 |
| 相机遮挡 | 低 | 备用视角 / 手动移除遮挡 |
| 抓取失败 | 中 | 重试机制 + 跳过该物体 |
| 电池不足 | 低 | 提前充电 + 备用电池 |
| 代码崩溃 | 中 | 自动重启脚本 + 快速恢复 SOP |

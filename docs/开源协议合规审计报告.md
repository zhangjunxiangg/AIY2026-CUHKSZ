## 1. 高危项详述

### 1.1 ultralytics = AGPL-3.0（🔴 法务必查项）

**引用点（import 确认）**：

| 文件 | 用途 | 性质 |
|---|---|---|
| `src/yolo-pipeline/03_smoke_train.py`、`04_train.py`、`05_evaluate.py`、`06_export.py` | 训练/评估/导出 | 开发期工具 |
| `src/perception/yolo_detect.py`（L67 `from ultralytics import YOLO`） | 运行时推理后端之一（`auto` 模式下优先选 ultralytics） | **产品运行时代码** |

**风险**：AGPL-3.0 是最强 copyleft，连网络服务使用都触发开源义务。只要仓库里有 `import ultralytics` 的代码，法务审查基本必挂。

**处置路线（三选一或组合）**：

1. **推理侧去 ultralytics（推荐）**：`yolo_detect.py` 已内置 `onnx` 后端（onnxruntime = MIT ✅）和 `rknn` 后端。训练时导出 `best.onnx` 后，运行时只需要 onnxruntime——把 `ultralytics` 后端整块删掉，`auto` 默认落到 onnx。改动约 20 行。
2. **训练管线剥离**：`src/yolo-pipeline/` 是开发工具（训练出模型权重即完成使命），可以不放进社区仓库；权重文件本身不构成 AGPL 的衍生作品（工具产出物），可安全分发。
3. 替代框架（重训练成本，不推荐现在做）：YOLOX（Apache-2.0）、YOLOv6（MIT）、或腾讯/百度的 Permissive 检测框架。

> 注意：ultralytics 另有企业付费许可，但与本场景无关；开源路线就是绕开它。

### 1.2 rf2o_laser_odometry = GPL-3.0（🔴，vendor 内）

- 位置：`vendor/kaihong-src/ros_ws/src/third_party/rf2o_laser_odometry/LICENSE`（全文 GNU GPL v3 已确认）
- 我们的代码**不引用它**（全库 grep `rf2o` 零命中），它是官方机器车源码自带的激光里程计包。
- 处置：随 vendor 归档整体不携带即规避。若最终决定带 vendor，必须剔除该目录。

### 1.3 许可不明包（🟡，vendor 内）

`ldlidar`、`ldlidar_driver`（我们的 bringup/检查脚本提到 ldlidar 驱动名）、`rviz_plugin`、`virtual_wall`：package.xml 里 license 字段为 `TODO`，目录内无 LICENSE 文件——**法律上等于"保留所有权利"**，比宽松协议更糟。同样靠"不带 vendor"规避。

## 5. 项目协议建议

**选 Apache-2.0**，理由：

1. M-Robots 核心项目（M-CLAW、robot_middleware 等）均为 Apache-2.0，与社区主协议对齐，法务最熟悉；
2. 允许商用、带专利授权条款，适合"作品落地社区"的定位；
3. 我们引入的全部依赖均与 Apache-2.0 兼容（处理掉 §1 高危项后）。

备选：木兰宽松许可证 V2（robot_docs 在用），同为开放原子系协议，中英双语法律效力对国内法务更友好。

落地动作：根目录放 `LICENSE`（Apache-2.0 全文）+ README 注明协议 + 第三方依赖列表（本报告 §2 可直接作为 `NOTICE` 素材）。

# 算法研究分工清单（Repo / 文档索引）

> 来源：《技术选型报告 v1.0》（见 `docs/技术选型报告/`）
> 用途：队长给队友分配赛前算法研究任务。每个方向独立成章，可直接按章认领。
> 硬件基线：RK3588S（6TOPS NPU，8GB RAM），M-Robots OS 4.1 + ROS1 noetic Docker
> 总原则：主链路零自研训练；经典算法全部用现成 ROS1 包；只有 YOLOv8n 需要在笔记本上微调后转 RKNN。

---

## 1. 底盘运动控制与避障

**任务**：麦轮里程计、EKF 定位融合、move_base 导航、雷达+深度实时避障。

### 主链路（必须吃透）

| 算法/组件 | 说明 | Repo / 文档 |
|---|---|---|
| 麦轮运动学+里程计 | 正逆解公式照抄，自写 ~100 行节点 | https://github.com/qaz9517532846/zm_robot （⭐136, Apache-2.0，四轮麦轮驱动/odom 节点可裁剪） |
| EKF 里程计融合 | 轮速 odom + IMU，麦轮横向打滑必融合 IMU | https://github.com/cra-ros-pkg/robot_localization （⭐2k+, BSD，`apt install ros-noetic-robot-localization`） |
| move_base 导航栈 | 全局/局部规划框架 | https://github.com/ros-planning/navigation （⭐2.6k, BSD，`apt install ros-noetic-navigation`，ARM64 直接装） |
| teb_local_planner | **主局部规划器**，`holonomic_robot: true` 唯一原生支持麦轮横向移动 | https://github.com/rst-tu-dortmund/teb_local_planner （⭐1.3k, BSD，`apt install ros-noetic-teb-local-planner`）；论文 Rösmann et al., RAS 2017 |
| dwa_local_planner | 保底，TEB 调不通即切换 | 含在 navigation 栈内 |
| depthimage_to_laserscan | Astra 深度→伪 LaserScan，作 costmap 第二障碍源（仅机械臂收回的导航态启用） | https://github.com/ros-perception/depthimage_to_laserscan （`apt install ros-noetic-depthimage-to-laserscan`） |
| RPLiDAR A1 驱动 | 主障碍源 | https://github.com/Slamtec/rplidar_ros （noetic 官方 deb） |
| AMCL / 纯里程计+IMU | 定位备份（Gemini 被碰/超时时切换） | 含在 navigation 栈内 |
| 麦轮全套参数模板 | move_base+TEB 的 launch/参数直接参考 | https://github.com/chenghao-li-1029/Mecanum_ros （麦轮+RPLiDAR+深度相机+导航全套） |

### 加分项（可选）

| 算法 | 说明 | Repo |
|---|---|---|
| TD3 DRL 避障 | 小 MLP，RK3588 CPU 可 10–20Hz 推理，权重需赛前自备 | https://github.com/reiniscimurs/DRL-robot-navigation （⭐1.3k, MIT） |

### 研究要点

- TEB 在 ARM 上偏重：`no_inner_iterations` 调 2–3 保实时；调不通退 DWA。
- 部署评估：odom+EKF 50–100Hz 占 <1 核 A55；costmap+TEB 5–10Hz 占 2 核 A76。
- 关键调参对象：costmap_2d 双障碍源（雷达主、伪激光备）、TEB 全向模式参数。

## 2. 抓取与手眼标定

**任务**：Astra（eye-in-hand）+ Gemini（俯视）识别目标 → 3D 定位 → 5DOF 臂+夹爪抓取。

### 主链路（必须吃透）

| 算法/组件 | 说明 | Repo / 文档 |
|---|---|---|
| 几何启发式两段式抓取 | Gemini 俯视粗定位 → Astra 精定位（深度分割→质心→反投影）→ <0.6m 盲区开环盲抓；自写，OpenCV+TF 实现 | 无现成 repo，架构参考见技术选型报告 §一.2 |
| easy_handeye 手眼标定 | **H0–3 第一优先级**，抓取链路最大单点失败源；采样 ≥15 组、各轴 ±90° | https://github.com/IFL-CAMP/easy_handeye （⭐1.1k, BSD，ROS1 noetic 开箱即用） |
| aruco_ros | 手眼标定用标记检测 | `apt install ros-noetic-aruco-ros` |
| 5DOF 解析 IK / 舵机轨迹 | 每次抓取 ms 级，跳过 MoveIt 用解析 IK；舵机直控话题 `/servo_controllers/port_id_1/id_pos_dur` | 板端 SDK 参考 `docs/板端开发参考/` |

### 备选 / 加分项（不进主链路）

| 算法 | 说明 | Repo / 论文 |
|---|---|---|
| GGCNN（62K 参数） | 深度图→抓取图，备选参考 | https://github.com/dougsm/ggcnn （⭐626）；论文 https://arxiv.org/abs/1804.05172 |
| GR-ConvNet（1.9M 参数） | 笔记本跑通做加分项；RKNN 转置卷积算子未验证，36h 不建议进链路 | https://github.com/skumra/robotic-grasping （⭐671, MIT）；论文 https://arxiv.org/abs/1909.04810 |
| Contact-GraspNet | ❌ 不推荐（安装链复杂需 GPU，5DOF+平行夹爪不需要） | 论文 https://arxiv.org/abs/2103.14127 |

### 研究要点

- Astra Pro Plus 最小测距 0.6m，末端近距离全盲——两段式是硬约束不是选择。
- 夹爪无压力传感器：固定闭合行程 + 堵转/电流检测 + 3s 超时松开。
- 可达性预筛：5DOF 垂直下抓可达区域有限，超出包络用全向底盘补偿。
- 几何启发式工时 4–8h、成功率 90–95%（纯色桌面简单几何体）；DL 方案 12–20h+ 且风险不可控。

## 3. 目标检测与方位距离识别

**任务**：识别 EVA 方块、小球、木圆柱、人形立牌、路锥，输出方位角+距离。

### 主链路（必须吃透）

| 算法/组件 | 说明 | Repo / 文档 |
|---|---|---|
| YOLOv8n INT8 RKNN @640 | **主板 NPU 单核**，纯推理 73.5 FPS / 端到端 ~30 FPS；每类 50–150 张现场采图微调 | https://github.com/airockchip/ultralytics_yolov8 （⭐800，RKNN 友好导出 fork） |
| Ultralytics 官方 RKNN 导出 | `model.export(format='rknn')` 官方集成 | https://github.com/ultralytics/ultralytics |
| rknn-toolkit2 | ONNX→RKNN INT8 转换链，赛前在笔记本预演一次 | https://github.com/airockchip/rknn-toolkit2 （⭐1.7k） |
| rknn_model_zoo | 官方 benchmark 源 + 各类 demo | https://github.com/airockchip/rknn_model_zoo （⭐2.7k） |
| HSV 颜色分割+轮廓 | 必备兜底，与 YOLO 按类别路由并联；EVA 彩块/橙路锥零训练，CPU <5ms | OpenCV 内置 |
| 中位深度+反投影 | 框内收缩 20% ROI 去零值取中位深度→内参反投影→TF；方位角 θ=atan2((u−cx)·Z/fx, Z) | 架构参考 https://github.com/MarkNaeem/depth_yolact_ros （检测+深度→3D 的 ROS1 架构可抄） |

### 备用

| 算法 | 说明 | Repo / 论文 |
|---|---|---|
| YOLO-World 零样本 | 备用权重烧辅助板，防某类训不出来；小物体召回不稳不作主力 | rknn_model_zoo 官方 demo（22 FPS 单核）；论文 https://arxiv.org/abs/2401.17270 |

### 不推荐

RT-DETR / YOLO-NAS（RKNN 链不成熟）、FoundationPose 等 6D 位姿（任务只需方位+距离）、GroundingDINO（RK3588 无法实时）、云端视觉推理（现场网络不可控）。

### 研究要点

- 数据策略：COCO 预标注+人工修正，1–2h 采集标注，笔记本/Colab 训练 30–60min。
- 人形立牌、木圆柱颜色先验弱，YOLO 微调是唯一可靠方案；HSV 兜不住这两类。
- 部署：模型 3.5MB、内存 <200MB，占 NPU 单核 <0.3 TOPS。

## 4. 字母点位与"马赛克"标定识别

**任务**：识别 A–D 印刷大字点位 + 疑似二维码/AprilTag 类标定物。

### 主链路（必须吃透）

| 算法/组件 | 说明 | Repo / 文档 |
|---|---|---|
| 模板匹配 | 二值化→轮廓→透视矫正→多尺度 matchTemplate；2–4h 工时，闭集 4 类印刷体足够 | OpenCV 内置 |
| 4 类微型 CNN（合成数据自训） | 与模板匹配并联投票；PIL.ImageFont 渲 A/B/C/D+增广 30min 出数据，模型 <500KB，CPU <5ms | 参考实现 https://github.com/Khalil071/EMNIST-Letter-Classification-using-CNN-and-ViT （注意 EMNIST 是手写体域，必须用场地字体合成数据自训） |
| OpenCV ArUco | 内置 ArUco 与 AprilTag2 字典，CPU 全帧 <15ms，零部署成本 | `pip install opencv-contrib-python`；教程 https://docs.opencv.org/4.x/d5/dae/tutorial_aruco_detection.html |
| AprilTag3 + apriltag_ros | 若主办方用 AprilTag，ROS topic 直出 | https://github.com/AprilRobotics/apriltag （⭐1.5k, BSD-2）+ https://github.com/AprilRobotics/apriltag_ros （noetic 分支） |
| cv2.QRCodeDetector | 若"马赛克"实为二维码，这是最优解 | OpenCV 内置 |
| ChArUco 标定板 | 赛前相机内参标定用 | OpenCV aruco 模块内置 |

### 备选

| 算法 | 说明 | Repo / 论文 |
|---|---|---|
| STag | 遮挡鲁棒但检测率略低，>40px 才稳定 | https://github.com/bdaiinstitute/stag ；论文 https://arxiv.org/abs/1707.06292 |
| PP-OCRv4 mobile | 仅当点位含数字编号/多字符才启用；整套 <20MB，RKNN 链路 8–14h | https://github.com/PaddlePaddle/PaddleOCR （⭐55k+, Apache-2.0）；RKNN 示例见 rknn_model_zoo |

### 不推荐

PARSeq / PP-OCRv5/v6（过重或转换链不成熟）、TopoTag（FMAC 基准检测率仅 57.65%）、任何云端 OCR API（现场网络不可靠）。

### 研究要点

- 赛题一公布就确认 marker 类型，现场打印备份（36h11 AprilTag、ArUco 6×6、二维码各若干）。
- 建议组合：先做「马赛克=fiducial 检测」+「字母=模板匹配」两条零深度学习管线（合计半天），再做 CNN 备份投票。
- 全部走主板 CPU（<15ms/帧），NPU 不占用。

## 5. LLM 任务规划与 VLA

**任务**：M-Claw 指令 → 任务拆解 → 动作原语 → 板端 FSM 执行 → 状态回报闭环。

### 主链路（必须吃透）

| 算法/组件 | 说明 | Repo / 论文 |
|---|---|---|
| LLM 原语 JSON + 板端 FSM | M-Claw（云端 Kimi/Qwen）→ 动作原语 JSON → 有限状态机 + 每步状态回报闭环重规划；~200 行 Python，8–12h | 学术背书：SayCan https://arxiv.org/abs/2204.01691 （affordance 列表）、ProgPrompt https://arxiv.org/abs/2209.11302 （结构化输出约束）、CaP https://arxiv.org/abs/2209.07753 |
| 断网降级 | 预定义任务模板 + 本地 FSM（对齐比赛手册 §5.4） | 自实现 |
| 话题接口 | `/task/command` 订阅、`/task/status` 发布（TaskStatus 五字段） | 见比赛手册 §10.2 |

### 仅路演叙事（不实机部署）

| 模型 | 参数量 | 36h 可用性 | Repo / 论文 |
|---|---|---|---|
| OpenVLA | 7B | ❌ 需 ≥16GB VRAM | https://arxiv.org/abs/2406.09246 |
| π0 / π0.5 | ~3B | ❌ GPU 推理+A100 微调 | https://arxiv.org/abs/2410.24164 / https://arxiv.org/abs/2504.16054 ；https://github.com/Physical-Intelligence/openpi |
| SmolVLA | ~450M | ⚠️ 唯一接近笔记本可行，但需 50–200 条真机示教数据；仅赛前有积累时作单技能 demo | https://arxiv.org/abs/2506.01844 ；https://github.com/huggingface/lerobot |
| EdgeVLA/MiniVLA/TinyVLA | — | ❌ RK3588 RKNN 无部署案例 | https://arxiv.org/abs/2507.14049 |

### 研究要点

- 路演话术：系统可平滑升级为 VLA 低层策略，RK3588 NPU 部署 VLA 是下一步工作。
- 核心工作量在 prompt 模板 + JSON schema 白名单校验 + 重试 + FSM 状态回报，不在模型本身。
- 语音识别走 M-Claw/Kimi 云端链路，触控屏输入做降级。

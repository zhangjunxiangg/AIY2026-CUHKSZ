### （3）深圳开鸿数字产业发展有限公司赛道

#### 现场场景组织方式

为兼顾开放创新与现场可执行性，现场场景采用"**统一测试区域 + 基础场景物料 + 团队自主搭建**"的组织方式。现场设置统一测试区域和基础场景物料，不针对每个作品方向单独搭建完整真实场景。

现场开发资源包括但不限于：

- 机器人测试区域
- 基础障碍物
- 点位标识
- 目标物、标签或二维码
- 已预装 M-Robots OS 的 KaihongBoard-3588S-SBC
- 驭系列-移动机器人
- 深度相机
- 可选传感器及交互模块（以现场实际配置为准）

参赛团队可在统一测试区域内，根据自身作品需要自主完成微型场景搭建，包括任务路线、目标物摆放、交互方式、演示流程和测试规则设计。

#### 作品呈现要求

可演示原型不要求达到产品级稳定性，但应能够在现场展示**核心任务流程、系统协同逻辑和主要交互效果**。

参赛团队应围绕一个相对完整、可理解、可演示的核心流程或关键交互进行作品呈现。例如：

```
用户指令或环境事件 → M-Claw 智能体运行时参与理解或规划 → 多设备之间协同 → 机器人或执行端产生可观察动作 → 系统反馈结果
```

如因时间、硬件或现场条件限制，部分能力无法完整实现，参赛团队可通过合理的**模拟、降级演示或流程说明**呈现设计思路。

评审重点包括：

1. 问题定义是否清晰
2. 系统逻辑是否成立
3. 技术路径是否合理
4. M-Robots OS 能力是否被有效结合
5. 现场演示是否具有说服力

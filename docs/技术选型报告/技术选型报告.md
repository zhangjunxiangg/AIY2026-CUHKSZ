# AIY 2026 黑客松（深开鸿 M-Robots OS 赛道）机器人算法技术选型报告

> 版本：v1.0（三轮审核后定稿）
> 日期：2026-08-05
> 硬件基线：KaihongBoard-3588S ×2（RK3588S：4×A76+4×A55，Mali-G610，6TOPS NPU×3核，8GB RAM，M-Robots OS 4.1 + ROS1 noetic Docker 运行时）；"驭"麦轮底盘 + 5DOF 机械臂 + 平行夹爪；Astra Pro Plus（手眼 RGBD）、思岚 A1 雷达、Gemini 335（场地俯视 RGBD）
> 约束：36 小时现场开发；现场实时可用；允许云端 API（M-Claw/Kimi/Qwen）；核心感知尽量端侧

---

## 〇、总体架构结论（TL;DR）

**三层算力分配：板端 CPU 跑控制与经典算法（90% 工作量）→ 板端 NPU 只跑一个 YOLOv8n 检测 → 云端 API 只做 LLM 指令解析与任务规划。笔记本仅作训练/标注/模型转换中转站，不进实时回路。**

五条铁律：

1. **不现场训练任何深度模型进实时回路**（除 YOLOv8n 检测可在笔记本上快速微调）；VLA 一律不实机部署，仅作路演叙事。
2. **导航用 ROS1 官方导航栈**：`move_base + teb_local_planner（全向模式）+ A1 雷达 + Astra 深度转伪激光`，全程 apt 安装零自研。
3. **抓取用几何启发式**（深度分割→质心→手眼 TF→垂直下抓），不用 GGCNN/GR-ConvNet 进主链路。
4. **字母/符号识别不用 OCR 管线**：A–D 用模板匹配+微型 CNN 投票；"马赛克"若是二维码/AprilTag 类用 OpenCV 内置检测器零成本解决。
5. **手眼标定是第 0–3 小时的第一优先级**，它是抓取链路的单点失败源。

### 1. 底盘运动控制与点到点避障

**任务**：麦轮里程计、定位、路径规划、依据障碍物（2D 雷达 + 深度）实时避障。

### 2. 夹爪目标定位与抓取 + 手眼标定

**任务**：Astra（eye-in-hand）识别 EVA 方块/小球/木圆柱 → 3D 定位 → 5DOF 臂抓取。

**首选管线（几何启发式，两段式，强烈推荐）**：
```
【粗定位】Gemini 335 俯视（固定安装、无运动污染）→ 检测+深度 → 静态 TF 直接给臂基座坐标
        （主源；绕开 Astra 0.6m 盲区与手眼标定误差放大）
【精定位】臂移至目标上方 ≥0.6m 处 → Astra depth → 固定 ROI/深度阈值去桌面 → 连通域
        → 质心(u,v)+中位深度 Z → 内参反投影 X=(u-cx)Z/fx, Y=(v-cy)Z/fy → 手眼 TF 对准
【盲抓段】进入 <0.6m 盲区后按缓存位姿开环下压（Astra Pro Plus 最小测距 0.6m，
        末端近距离深度全盲，必须两段式）
（夹爪旋转角：方块/圆柱用轮廓最小外接矩形；球直接垂直抓）
```
**可达性预筛**：5DOF 臂垂直下抓（pitch=−90°）全姿态可达区域有限——目标超出包络时用麦轮底盘移动补偿（全向底盘正好配合），抓取前先查可达性表。
**夹爪闭合策略**：无压力传感器 → 固定闭合行程 + 舵机堵转/电流检测（若舵机支持）+ 3s 超时松开（与手册安全边界一致）。

**手眼标定**：`IFL-CAMP/easy_handeye`（⭐1.1k，BSD，ROS1 noetic 开箱即用）+ `ros-noetic-aruco-ros` 标记。采样 ≥15 组、各轴旋转 ±90°，**第 0–3 小时完成**，标定误差是抓取链路最大单点失败源。

**深度学习备选（不进主链路）**：

| 方案 | 论文 | 代码 | 评估 |
|---|---|---|---|
| GGCNN（62K 参数，深度图→抓取图）| arXiv:1804.05172 | dougsm/ggcnn ⭐626（TF，ARM 环境坑多）| 备选参考 |
| GR-ConvNet v1/v2（1.9M 参数，PyTorch CPU 可推理）| arXiv:1909.04810 | skumra/robotic-grasping ⭐671（MIT）| 笔记本跑通做加分项；**RKNN 转换需验证转置卷积算子，36h 不建议** |
| Contact-GraspNet（6DoF 点云抓取）| arXiv:2103.14127 | 安装链复杂需 GPU | ❌ 5DOF+平行夹爪+简单几何体完全不需要 |

**36h 工时/成功率权衡**：几何启发式 4–8h、成功率 90–95%（纯色桌面简单几何体）；DL 方案 12–20h+ 且域偏移/转换链风险不可控。结论明确：**几何启发式为主，DL 仅加分**。

**部署评估**：

| 模块 | 调用频率 | 算力 | 部署位置 |
|---|---|---|---|
| 深度分割/质心（OpenCV）| 每次抓取 1 次（~50ms）| <1 核 | 主板 CPU |
| 手眼标定 | 赛前一次性，之后静态 TF | CPU | 主板（笔记本 RViz 观察）|
| 5DOF 解析 IK / 舵机轨迹 | 每次抓取，ms 级 | <1 核 | 主板 CPU（5DOF 可跳过 MoveIt 用解析 IK）|
| GR-ConvNet 推理（备选）| 每次抓取 1 次 | PyTorch CPU ~50ms（笔记本）| 笔记本外侧算力（不进实时回路）|

### 3. 目标检测与物体方位距离识别

**任务**：识别 EVA 方块、小球、木圆柱、人形立牌、路锥，输出方位角+距离。

**首选**：`YOLOv8n INT8 RKNN @640，主板 NPU`（Rockchip 官方 benchmark 单核 73.5 FPS；社区端到端实测单核 30 FPS / 三核 60 FPS，INT8 mAP 损失 ~1.2%）→ 框内收缩 20% ROI 去零值取**中位深度** → 反投影 + TF 发布。方位角 θ = atan2((u−cx)·Z/fx, Z)。

**三条路线可行性排序（36h 极少数据）**：

1. 🥇 **YOLOv8n 现场采图快速微调**：每类 50–150 张 + 增广（1–2h 采集标注，COCO 预标注+人工修正），笔记本/Colab 训练 30–60min，airockchip fork 导出 ONNX→rknn-toolkit2 INT8。对人形立牌、木圆柱（颜色先验弱）是唯一可靠方案。
2. 🥈 **HSV 颜色分割+轮廓（必备兜底，并联运行）**：EVA 彩块、橙色路锥零训练即得，CPU <5ms；与 YOLO 按类别路由互为冗余。
3. 🥉 **YOLO-World 零样本（备用权重烧辅助板）**：rknn_model_zoo 有官方 demo（22 FPS 单核），防某类训不出来；小物体召回不稳，不作主力。

**不推荐**：RT-DETR/YOLO-NAS（RKNN 部署链不成熟）、FoundationPose 等 6D 位姿（任务只需方位+距离，RGBD 直接测距更准更快）、GroundingDINO（RK3588 无法实时）、云端视觉推理（现场网络不可控）。

**关键论文/资源**：
- YOLOv8 / YOLO11（Ultralytics docs；官方 RKNN 集成 `model.export(format='rknn')`）
- YOLO-World：arXiv:2401.17270（CVPR 2024）
- RK3588 检测器实测数据：eBirdNet（MDPI Electronics 2026，给出 v8n 12.93ms@320 INT8 等毫秒级延迟表）
- 代码：airockchip/rknn_model_zoo ⭐2.7k（官方 benchmark 源）、airockchip/rknn-toolkit2 ⭐1.7k、airockchip/ultralytics_yolov8 ⭐800（RKNN 友好导出）、MarkNaeem/depth_yolact_ros（检测+深度→3D 的 ROS1 架构可抄）

**部署评估**：

| 模块 | 调用频率 | 算力 | 实测 FPS | 部署位置 |
|---|---|---|---|---|
| YOLOv8n INT8@640 | 30 Hz 连续 | NPU 单核 <0.3 TOPS 占用，模型 3.5MB，内存 <200MB | 单核 73.5（纯推理）/ ~30（端到端）| **主板 NPU 核0** |
| HSV 分割+轮廓 | 30 Hz | CPU <5ms | >150 | 主板 CPU（与 NPU 并联）|
| 中位深度+反投影 | 30 Hz | <2ms | >200 | 主板 CPU |
| YOLO-World v2s（备用）| 按需 1–5 Hz | NPU + CLIP 文本编码 | 22 | 辅助板 NPU |

### 4. 字母点位识别与"马赛克"/符号标定

**任务**：识别 A–D 印刷大字点位 + 疑似二维码/AprilTag 类标定物。

| 子任务 | 首选 | 备选 | 不推荐 |
|---|---|---|---|
| A–D 字母（已知字体闭集 4 类）| **模板匹配（二值化→轮廓→透视矫正→多尺度 matchTemplate，2–4h 工时）+ 合成数据 4 类微型 CNN（<1MB，CPU <5ms）并联投票** | PP-OCRv4 mobile（整套 <20MB，RKNN 链路 8–14h，对 4 类大字过度设计）| PARSeq/PP-OCRv5/v6（过重/转换链不成熟）；EMNIST 预训练（手写体域不匹配，须用场地字体合成数据自训）|
| "马赛克"标定物 | **OpenCV `cv2.aruco`**（内置 ArUco 与 AprilTag 字典，CPU 全帧 <15ms）；若是 AprilTag 用 AprilRobotics/apriltag + apriltag_ros（ROS topic 直出）；若是二维码用 `cv2.QRCodeDetector` | STag（遮挡鲁棒但检测率略低）| TopoTag（FMAC 基准检测率仅 57.65%）|

**关键论文**：PP-OCR 系列（arXiv:2009.09941 / 2109.03144 / 2206.03001 / 2507.05595）、AprilTag 2（Wang & Olson, IROS 2016 会议论文，无 arXiv 版）、STag（arXiv:1707.06292）、FMAC 四系统位姿精度对比（arXiv:2601.07723）。

**部署评估**：全部走主板 CPU（<15ms/帧），NPU 不占用；云端方案因现场网络不可靠一律不推荐。

**补充物料**：EVA 套环与收纳筐——套环用 HSV/轮廓定位环心，动作原语增加 `place_ring(post)`（抓取→移动到立柱上方→垂直下放套入，属精细放置，比投放难一档，建议 P2 再做、现场先验证臂垂直下放的重复定位精度）；收纳筐用 HSV 颜色/轮廓定位筐口中心，投放对准策略=俯视 Gemini 粗定位筐口 + 臂移到筐口上方开环松爪（筐口大、容差大，P1 即可做）。

### 5. LLM 任务规划与 VLA 可行性

**唯一可行路线（推荐）**：M-Claw（云端 Kimi/Qwen）→ 动作原语 JSON → 板端有限状态机执行 + 每步状态回报闭环重规划。学术背书：该架构 = SayCan（arXiv:2204.01691）的 affordance 列表 + ProgPrompt（arXiv:2209.11302）的结构化输出约束。实现 ~200 行 Python（prompt 模板 + JSON schema 白名单校验 + 重试 + FSM），8–12h。

**VLA 评估结论（明确：36h 不实机部署）**：

| 模型 | 论文 | 参数量 | 36h 可用性 |
|---|---|---|---|
| OpenVLA | arXiv:2406.09246 | 7B | ❌ 需 ≥16GB VRAM，RK3588 8GB 不可能 |
| π0 / π0.5 | arXiv:2410.24164 / 2504.16054 | ~3B | ❌ GPU 推理+A100 微调+需本体数据 |
| SmolVLA | arXiv:2506.01844 | ~450M | ⚠️ 唯一接近笔记本可行，但需 50–200 条真机示教数据；自定义 5DOF 臂无现成数据 → 仅赛前有积累时可作单技能亮点 demo |
| EdgeVLA/MiniVLA/TinyVLA | arXiv:2507.14049 等 | — | 前沿研究，RK3588 RKNN 无部署案例 |

**路演话术**：引用上述工作说明"系统可平滑升级为 VLA 低层策略，RK3588 NPU 部署 VLA 是下一步工作"。

**部署评估**：

| 组件 | 调用频率 | 算力 | 部署位置 |
|---|---|---|---|
| 语音识别（ASR）| 按需 | 云端 | **M-Claw/Kimi 云端链路**，触控屏输入降级（与手册 §4.1/§12.1 对齐）|
| M-Claw 指令解析/任务拆解 | 按需（每指令 1 次）| 云端大模型 | **云端 API**（断网降级：预定义任务模板本地 FSM）|
| 原语 JSON → FSM | 0.1–1 Hz 步进 | 可忽略 | 主板 CPU |
| 状态回报 → 闭环重规划 | 每原语完成/失败时 | 云端 | 云端 API |
| SmolVLA demo（备选亮点）| 5–10 Hz | ~450M bf16 | 笔记本（灰色地带，不进主链路）|

**与手册的两处显式偏离（答辩备用）**：① YOLOv8n 部署在**主板 NPU**而非手册 §4.1 的辅助板——手册 §4.2 自身也写主板 NPU，且手眼相机 Astra 在主板，检测直接服务抓取/测距，跨板传输徒增延迟；辅助板专职 Gemini 俯视。② **TEB 替代 DWA 为主**局部规划器——TEB 是 ROS1 唯一原生支持麦轮全向横向移动的成熟局部规划器，DWA 仅作保底。③ 点云/雷达角色与手册互换（雷达为主、点云为备）更省 CPU，保留 PCL voxel_layer 兜底配置。
**定位备份**：Gemini 被碰/网络超时时切 AMCL 或纯里程计+IMU（手册方案 A，§2.1/2.3）。
**软总线加分项（P3）**：双板间用 M-Robots OS 分布式软总线做状态同步/文件共享，直接对应评分表"M-Robots OS 能力结合"25 分；路演话术强调全部感知推理在板端完成。

## 三、工程风险与对策

1. **Astra Pro Plus 驱动老旧**：官方 ROS wrapper 已 limited maintenance，noetic ARM64 需走 legacy OpenNI 栈源码编译（社区有修补 fork）；Gemini 335 全维护。**对策：赛前烧好含驱动的镜像；主识别优先 Gemini，Astra 仅作手眼。**
2. **OpenHarmony 硬约束**：musl libc、只读 rootfs、无 systemd → ROS 全栈必须跑在 Ubuntu 20.04 Docker 内，`--privileged` 映射 /dev/rknpu、/dev/ttyUSB*；无 systemd 用启动脚本拉起 roscore。
3. **麦轮横向漂移**：纯轮速里程计不可用，IMU 融合不可省。
4. **TEB 在 ARM 偏重**：`no_inner_iterations` 调 2–3；调不通退回 DWA。
5. **网络断连**：云端 LLM 断线时降级为预定义任务模板 + 本地 FSM（与比赛手册 §5.4 一致）。
6. **GR-ConvNet RKNN 转置卷积算子支持未验证** → 只作加分项，主链路不依赖。

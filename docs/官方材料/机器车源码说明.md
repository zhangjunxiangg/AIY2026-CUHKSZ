## 2. M-Claw 快速上手



在小车开发板终端 M-Terminal 启动 M-Claw：

```sh
 run mclaw
```

如果需要接入微信通道使用M-CLAW，请先输入以下指令扫码链接微信：

```sh
 run mclaw weixin login
```

登陆后开启M-CLAW微信会话:

```sh
 run mclaw weixin
```

进入 M-Claw 后可直接使用自然语言，无需输入脚本路径。

建议首先检查整机状态：

```text
返回底盘、雷达和机械臂状态
```

常用说法：

```text
列出比赛可用的 ROS 接口
返回雷达状态和一帧扫描检测值
用深度相机拍一张彩色图和深度图，并显示拍摄结果
运行颜色分类
停止底盘
```

涉及底盘或机械臂真实运动时，应明确给出方向、速度、持续时间或目标舵机位置，
并提前确认周围环境安全。例如：

```text
以 0.1 m/s 的速度向前移动 3 秒
把机械臂舵机 ID3 调整到 500
把夹爪舵机 ID10 调整到 600
```

## 3. M-Claw Skill 能力说明

### 3.1 常用操作示例

| 能力 | 自然语言示例 | 结果与限制 |
|---|---|---|
| 检查整机状态 | `返回底盘、雷达和机械臂状态` | 只读操作，不触发运动 |
| 控制底盘 | `以 0.1 m/s 的速度向前移动 3 秒` | 必须明确方向、速度和持续时间 |
| 读取机械臂 | `返回机械臂当前舵机值` | 返回当前舵机反馈值 |
| 调整机械臂 | `把机械臂舵机 ID3 调整到 500` | 一次只调整一个 ID |
| 控制夹爪 | `把夹爪舵机 ID10 调整到 600` | 必须单独、明确要求夹爪动作 |
| 读取雷达 | `返回雷达状态和一帧扫描检测值` | 只读取 `/scan`，不会移动底盘 |
| 拍摄 Astra RGB-D | `用深度相机拍一张彩色图和深度图，并显示拍摄结果` | 固定覆盖最新 RGB、16 位深度图、深度预览和 JSON |
| 运行四色分类 | `运行颜色分类` | 只返回感知结果和分拣建议，不自动抓取 |
| 连接辅助相机 | `连接辅助相机 <辅助板IPv4>` | 必须提供辅助板当前 IPv4，不猜测或沿用旧地址 |
| 查看辅助相机照片 | `查看辅助相机最新照片` | 返回同一局域网可访问的 JPG 地址，默认共享 10 分钟 |

### 3.2 辅助相机使用注意事项

Gemini 335 驱动运行在独立辅助开发板上，而 M-Claw 运行在小车开发板上。使用辅助相机时：

1. 在辅助板终端中，用小车当前 IP 完成配置并启动相机；
2. 回到小车终端启动 M-Claw；
3. 向 M-Claw 明确提供辅助板**当前 IPv4**。

```text
连接辅助相机 <辅助板IPv4>
检查辅助相机状态，辅助板 IP 是 <辅助板IPv4>
拍一张辅助相机的 RGB-D，辅助板 IP 是 <辅助板IPv4>
查看最新照片
```

M-Claw 只会在小车侧核对 ROS 图像话题的发布源并接收真实 RGB-D 数据，不会在
辅助板上执行本地命令。不得让 M-Claw 猜测、扫描或沿用旧 IP。

## 6. Gemini 335 辅助相机

Gemini 335 的驱动和图像预处理运行在独立辅助板上，小车作为 ROS Master。更换
Wi-Fi 或小车 IP 后，需要在辅助板上重新配置。

### 6.1 在辅助板上配置和启动

```sh
/data/gemini335/configure-car-ros.sh <小车当前IP>
/data/gemini335/start-gemini335.sh
/data/gemini335/status-gemini335.sh
```

`start-gemini335.sh` 会检查是否收到真实深度帧；如果 USB 端点没有及时恢复，会
自动重启容器一次。只有 `status-gemini335.sh` 同时显示以下结果，才表示数据链路
可用：

```text
DEPTH_FRAME=PASS
COMPRESSED_COLOR_FRAME=PASS
```

### 6.2 小车侧 ROS 接口

```text
/aux_camera/color/image_raw/compressed   JPEG 彩色图，默认最高 5 fps
/aux_camera/depth/image_raw              配准深度图，16UC1，单位 mm
/aux_camera/color/camera_info            彩色相机内参
/aux_camera/depth/camera_info            深度相机内参
```

一次性接收并解码 RGB-D：

```sh
/data/robot-host/student/tools/receive-aux-rgbd-once.sh
```

输出固定覆盖到 `/data/robot-host/student/output`，不会按时间戳累计文件：

```text
aux-camera-latest-color.jpg
aux-camera-latest-depth.png
aux-camera-latest-depth-preview.pgm
aux-camera-latest.json
```

输出包括 JPEG 彩色图、16 位 PNG 深度图、PGM 深度预览和 JSON 元数据。接收工具
不依赖小车宿主环境中的 OpenCV，以避免 Python/OpenCV ABI 版本冲突。

比赛程序建议在辅助板上完成视觉识别，只向小车发布目标坐标、时间戳和置信度。
原始深度数据主要用于标定、调试或按需定位。

## 7. 深度相机四色分类 Demo

Demo 位置：

```text
/data/robot-host/student/demo/color_sorting
```

功能：检测红、黄、绿、蓝目标，并返回颜色置信度和建议收纳区。

运行方式：

```sh
/data/robot-host/student/demo/color_sorting/run-color-sorting-demo.sh
```

结果固定覆盖到：

```text
/data/robot-host/student/output/color-sorting/latest-color-sorting.jpg
/data/robot-host/student/output/color-sorting/latest-color-sorting-depth-preview.jpg
/data/robot-host/student/output/color-sorting/latest-color-sorting.json
```

运行期间，程序还会将 JSON 字符串发布到：

```text
/student/color_sorting/decision
```

`recommendation_ready` 表示颜色分类和分拣建议可用。由于 Demo 未使用当前实车的
手眼外参，`pick_ready` 始终为 `false`。不得直接把 Demo 输出的相机坐标作为
`base_link` 下的抓取坐标。

相机测得的目标位置必须先转换到任务所需坐标系。是否需要某项标定取决于使用场景，
但用于定位或抓取的外参必须由参赛者在当前实车和当前安装状态下完成标定。

### 8.1 板载 Astra 到机械臂

说明文档：

```text
/data/robot-host/astra-arm-calibration/student/README.md
```

### 8.2 辅助相机到比赛地面

用于目标地面位置、小车中心和车头朝向，不可用于机械臂三维抓取：

```text
/data/robot-host/student/calibration/auxiliary/aux-ground-calibration.py
```

### 8.3 辅助相机到机械臂 `base_link`

用于机械臂 IK 和三维抓取：

```text
/data/robot-host/student/calibration/auxiliary/aux-arm-handeye.py
```

辅助相机的完整标定说明：

```text
/data/robot-host/student/calibration/auxiliary/README.md
```

地面移动标定与机械臂手眼标定用途不同，必须分别采集、求解和验收。相机位置、角度、
分辨率或安装支架发生变化后，对应外参必须重新标定。

## 9. 参赛程序开发建议

建议新建独立的 catkin 工作区和 ROS 包。任务状态机至少应包含：

1. 启动前健康检查；
2. 目标检测、深度对齐和时间戳新鲜度检查；
3. 根据任务选择正确的地面定位外参或机械臂手眼外参；
4. 导航和底盘对齐；
5. 抓取前重新检测，并完成 IK、碰撞和运动行程检查；
6. 夹取、抬升、运输和放置；
7. 每一步的超时、失败重试和异常情况下的零速停车。

建议的最小 ROS 包结构：

```text
student_tasks/
├─ CMakeLists.txt
├─ package.xml
├─ config/
│  └─ my-scene.yaml
├─ launch/
│  └─ task.launch
└─ scripts/
   └─ task_node.py
```

参赛者程序应通过已有 Topic、Service 和 Action 调用底层能力，无需重新编写 STM32、
雷达、相机或舵机驱动。

AIY黑客松·开发第五步

迭代反思卡使用指南

开发中期用一次，防止一条路走到黑

一、为什么中期要停下来反思一次？

你有没有过这种经历：

• 写了半天代码，发现方向偏了，但不甘心重来，硬着头皮做完，路演时评委一句"这个功能有意义吗"全盘崩溃

• 团队三个人各干各的，到中途才发现做的东西拼不到一起

• 有个功能卡了很久，谁都没发现，最后时间不够只能放弃

• 路演完才想明白"其实应该那么做"——但已经晚了

反思不是赛后的总结，是赛中的方向盘。

黑客松时间紧，很容易陷入"埋头干"模式。但如果你一直低头干、从不抬头看，很可能到终点才发现跑错了道。

中期停下来一会儿，抬头看看：

• 我们还在解决最初那个问题吗？

• 现在做的东西能演示吗？

• 有没有更简单的方法达到同样效果？

• AI 用得对不对？

然后调整方向，继续干。就这一次，不会打断你们太多开发节奏。

关键原则：反思不是为了批评谁，是为了在还能改的时候及时改。

二、什么时候做这次反思？

核心功能刚跑通的时候。

也就是：用户输入→AI 处理→输出结果这条主线能走通了，哪怕界面还很糙、哪怕只有一种情况能跑通。

这个时候反思价值最大：

• 太早（主线还没通）——没什么可反思的，都在搭框架

• 太晚（快路演了）——发现问题也没时间改了

• 刚刚好（主线通了但还没打磨）——能改方向、能砍功能、能补漏洞

💡 中学版：主线能跑通就立刻做，不用想太多。  💡 大学版：同样在主线跑通后做。如果项目复杂度高、有多个模块，可以在最重要的模块跑通时做。

三、反思四步法（中学版）

用的是经典的「开始做 / 停止做 / 继续做」框架——简单、好上手、不绕弯子。

第一步：回头看

全队快速回答三个问题——

✅ 做得好的——继续做：

• 从开始到现在，哪些事做得对？哪些决策被验证是对的？

• 例：我们一开始就决定只做"拍照→识别→提醒"这条主线，没加花里胡哨的功能，现在看是对的。

❌ 做得不好的——停止做：

• 哪些事浪费时间了？哪些做法行不通？

• 例：我们花了两小时调方言语音合成的参数，结果还是不够自然——这个方向先停，用标准语音先跑通。

🔄 还没做但应该做的——开始做：

• 有什么重要的事一直拖着没做？现在必须开始了？

• 例：我们还没测过奶奶真的能看懂界面上的字——得找个老人试一下。

第二步：对着问题定义卡检查

拿出你们第一步填的问题定义卡，对照检查——

| 检查项 | 回答 |
|---|---|
| 我们现在做的东西，还在解决卡上写的那个问题吗？ | □是 □偏了（偏去哪了：______） |
| 核心功能跑通了吗？能演示给用户看了吗？ | □能 □不能（卡在哪：______） |
| 有没有加了问题定义卡上没有的功能？为什么加的？ | □有 □没有 |
| 问题定义卡上写的"成功指标"，现在能测了吗？ | □能 □不能 |

⚠️ 如果第三题答"有"——对着问题定义卡判断：这个新功能解决的是卡上写的那个麻烦吗？不是就砍掉。

第三步：定下一步

基于上面的检查，全队商量——

接下来要做的 3 件事（按优先级排）：

1. _____________________________________________________________

1. _____________________________________________________________

1. _____________________________________________________________

每件事指定一个人负责，说清楚什么时候做完：

| 事情 | 谁负责 | 什么时候做完 |
|---|---|---|
|  |  |  |
|  |  |  |
|  |  |  |

💡 只列 3 件。列 10 件等于没列。选最关键的 3 件，做完再说下一步。

第四步：全队确认

每个人回答一句——

"我觉得接下来我们能按计划做完，因为______。"

或

"我担心______，建议______。"

如果有人说了"担心"——PM 快速判断：要不要现在处理？如果是影响核心功能的大问题——现在就处理。如果是小问题——记下来，继续干。

四、反思四步法（大学版）

用的是 AAR 事后复盘法 + OODA 决策循环 的融合——AAR 来自美国陆军，OODA 来自战斗机飞行员决策模型，两个都是为"高压+时间紧"场景设计的，比 Gibbs 反思循环更适合黑客松中期。

💡 为什么不用 Gibbs？Gibbs 的"感受"步骤在中期反思里是浪费——你描述完"技术卡住了"，大家说"我很焦虑"，然后呢？焦虑不会因为说出来就消失。中期反思要的是"卡在哪→换什么方案→谁去做"，不是"我有什么感受"。Gibbs 更适合赛后系统复盘。

第一步：对照（Observe + 原计划 vs 现实）

拿出问题定义卡，对比"原计划"和"现状"：

| 维度 | 原计划（问题定义卡上写的） | 现状（实际做到的） | 差异 |
|---|---|---|---|
| 核心问题 |  |  | □一致 □偏了 |
| 目标用户 |  |  | □一致 □偏了 |
| 核心功能 |  |  | □通 □没通 |
| 演示路径 |  |  | □通 □没通 |

例：原计划做"拍照识别药盒→方言提醒"，现状是识别通了但方言合成卡住，差异在"方言"这一环。

第二步：归因（Orient + 根因分析）

差异从哪来？连问 2 个"为什么"（不要超过 2 个，挖太深会拖时间）：

• 为什么有这个差异？→ ________

• 为什么会这样？→ ________

根因类型（选一个，决定第三步的方向）：

• □ 技术选型问题（工具不对）→ 第三步考虑换工具

• □ 信息不足（没查文档/没调研）→ 第三步派人去查

• □ 分工问题（没人负责/重复劳动）→ 第三步重新分工

• □ 范围问题（想做太多）→ 第三步砍功能

• □ 目标问题（问题定义卡本身错了）→ 第三步改目标

例：方言合成卡住→为什么？因为没查过这个工具支不支持方言→为什么？因为调研同学在做用户调研没帮技术查文档。根因类型：信息不足。

第三步：决策（Decide + 方案对比）

基于根因，列出 2-3 个方案对比（必须包含"降级/放弃"选项）：

| 方案 | 怎么做 | 代价 | 开发周期能完成吗 |
|---|---|---|---|
| 方案A（最优） |  |  | □能 □不能 |
| 方案B（次优） |  |  | □能 □不能 |
| 方案C（降级/放弃） |  |  | □能 □不能 |

我们选：方案____，因为________________

💡 黑客松中期，"能完成的次优方案"永远好过"做不完的最优方案"。如果方案A和B都"不能完成"，直接选方案C。这一步是大学版和中学版最大的区别——中学版直接定任务，大学版要先对比方案再定。

第四步：行动（Act + 行动交接）

接下来立刻要做的 3 件事：

| 事情 | 谁负责 | 什么时候交 | 卡住了找谁 |
|---|---|---|---|
|  |  |  |  |
|  |  |  |  |
|  |  |  |  |

全队确认： 每人说一句"我同意这个方案，因为______"或"我担心______，建议______"。

💡 大学版的反思比中学版多了"方案对比"环节，但要控制时间别拖太久。如果根因分析发现根因很复杂——记下来，赛后深入研究，比赛中先按当前最优解走。

五、AI 黑客松特有的反思维度

普通黑客松的反思主要看"功能做完了没"。AI 黑客松不一样——还得反思 AI 用得对不对。

这次反思中，额外检查这 4 个 AI 维度——

🤖 AI 维度一：AI 的输出可靠吗？

| 问题 | 怎么检查 |
|---|---|
| AI 返回的结果稳定吗？ | 同一个输入测 5 次，看输出是不是基本一致 |
| 有没有出现"幻觉"（AI 编造不存在的信息）？ | 拿 AI 输出和真实数据对比，看有没有编造 |
| 边界情况表现怎么样？ | 试试空输入、超长输入、奇怪格式输入，看会不会崩 |

例：拍照识别药盒的项目——如果拍到一个 AI 不认识的药盒，它会编一个药名出来吗？还是会说"我不认识，请手动输入"？这两种设计对老人来说完全不同。

🤖 AI 维度二：AI 真的比非 AI 方案好吗？

| 问题 | 怎么检查 |
|---|---|
| 这个功能不用 AI 能做吗？ | 想想有没有更简单的替代方案（规则、模板、手动） |
| AI 带来的好处值得它的成本吗？ | AI 可能不稳定、有延迟、要花钱——好处够大吗？ |

例：如果只是把作业通知从群消息里提取出来——用关键词过滤可能比大模型更快更稳。但如果不同老师的作业通知格式千差万别，AI 就有意义了。

🤖 AI 维度三：伦理和公平检查

| 问题 | 怎么检查 |
|---|---|
| 我们的 AI 会不会对某些人不友好？ | 想想：不会打字的人、有口音的人、老年人、视障人士能用吗？ |
| 训练数据/提示词有没有偏见？ | AI 会不会默认某些假设（比如默认用户是年轻人、默认家庭结构是核心家庭）？ |
| 用户隐私保护了吗？ | 我们收集的数据存哪了？用户知道吗？比赛结束后会删吗？ |

例：方言语音提醒功能——如果只支持普通话和粤语，听不懂普通话的少数民族老人怎么办？至少在界面上标注"目前支持 XX 语言"。

🤖 AI 维度四：提示词和工作流可以优化吗？

| 问题 | 怎么检查 |
|---|---|
| 提示词还有没有可以改进的空间？ | 看看 AI 输出不理想的地方，是不是提示词不够清楚 |
| 工作流可以简化吗？ | 有没有多余的步骤可以合并或删掉？ |
| 有没有更好的 AI 工具替代？ | 当前用的工具是不是最适合这个任务？ |

例：如果用大模型做药盒识别，发现准确率不够——是不是可以先用 OCR 提取文字、再让大模型判断药名？两步比一步可能更准。

六、一个完整的反思示例

以"帮奶奶管血压的 AI 小助手"为例，在核心功能跑通时做一次中期反思——

✅ 做得好的——继续做

• 只做了"语音输入血压→AI生成趋势图→方言提醒"这条主线，没加花里胡哨的功能

• 用扣子 Coze 搭工作流，比纯写代码快很多

• 界面字很大，奶奶能看清

❌ 做得不好的——停止做

• 花了一小时调方言合成的语速参数，其实标准语速就够用

• 趋势图的颜色太花，老人看不懂红黄绿代表什么

🔄 还没做但应该做的——开始做

• 还没让真正的老人试过——得找个爷爷奶奶测一下

• 提醒声音太小，奶奶听力不好，得调大或者加振动

• 没有做"数据删除"功能——比赛后展示用的数据应该能清空

对着问题定义卡检查

| 检查项 | 回答 |
|---|---|
| 还在解决卡上写的那个问题吗？ | ✅ 是 |
| 核心功能能演示了吗？ | ✅ 能 |
| 有没有加了卡上没有的功能？ | ❌ 加了"每日健康小贴士"——砍掉 |
| 成功指标能测了吗？ | ⚠️ 部分——能记录血压数据，但还没测过"连续4周使用率" |

AI 维度检查

| 维度 | 发现 |
|---|---|
| AI 输出可靠性 | 语音输入血压数字时，AI 有时会把"130"听成"三十"——需要在提示词里加"请确认数字是否在合理血压范围内" |
| AI vs 非AI | 趋势图其实不需要AI——用普通图表就够了。AI 真正的价值在语音转文字和方言合成 |
| 伦理公平 | 方言只支持普通话和粤语，其他方言的老人用不了——界面要标注 |
| 提示词优化 | 可以加一句"如果数字看起来不像血压（比如超过300或低于50），请提醒用户重新输入" |

接下来要做的 3 件事

| 事情 | 谁负责 | 什么时候做完 |
|---|---|---|
| 砍掉"每日健康小贴士"功能 | 技术 | 现在立刻 |
| 找一个老人测试，观察TA能不能独立完成"量血压→语音输入→看趋势图" | 调研 | 接下来优先做 |
| 加输入校验：血压数字异常时AI提醒重新输入 | 技术 | 路演准备前 |

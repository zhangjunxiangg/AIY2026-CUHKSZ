## 2. 为什么不能直接推完整历史

GitCode 项目钩子限制**单文件 ≤ 10 MiB**，而我们的开发历史里有 8 个超限文件（4 个路演 PDF、3 个官方模型二进制、1 个调试视频）。这些文件已从当前工作树和跟踪中移除，但**仍存在于历史提交**中，直接 `git push gitcode main` 会被 pre-receive 钩子拒绝。

因此社区仓采用**单提交嫁接导入**：每次同步 = 以 gitcode main 最新提交为父、当前 main 的文件树为内容，生成一个新提交推上去。GitHub 历史不受影响。

## 4. 再次同步的操作步骤

**直接用脚本（推荐）**：

```bash
git pull                              # 确保 main 最新
bash scripts/sync-gitcode.sh "sync: 一句话说明本次内容"
```

脚本会自动：fetch gitcode → 以 main 树构造社区仓树（**替换 README 为 `docs/社区仓README.md` 公开版**，剔除内部协作文档：本指引、清理指南、`prep/git协作约定.md`）→ 以 gitcode/main 为父生成嫁接提交 → 推送。过滤清单在脚本顶部 `EXCLUDE_PATHS`，需要增删改那里。

手动等效命令（理解原理用）：

```bash
# 1. 取 gitcode main 当前头
git fetch gitcode
GC_HEAD=$(git rev-parse gitcode/main)

# 2. 用当前 main 的树 + gitcode main 为父，生成嫁接提交
NEW=$(git commit-tree main^{tree} -p $GC_HEAD -m "sync: 同步 GitHub main @ $(git rev-parse --short main)（一句话说明本次内容）")

# 3. 更新同步分支并推送
git branch -f gitcode-release $NEW
git push gitcode gitcode-release:main
```

推送时钩子会重新检查：只要工作树里没有新的 >10MiB 跟踪文件，必然通过。

## 5. 内容边界（同步到社区仓的内容纪律）

以下内容**永不进入**社区仓（已 gitignore，commit-tree 取的是跟踪树，天然不含）：

- `vendor/`（官方源码归档）、`AIY文件/`、`docs/官方材料/`——官方/机器人自带内容
- `docs/kimi-prompts/`、`docs/队长卡片/`、`docs/社区贡献issues/`、里程碑回顾等私人内容（见 .gitignore 豁免区）
- `presentation/deck/*.pdf`、`*.mp4` 等大文件（HTML 源文件在库，可重新导出）
- `src/yolo-pipeline/`（AGPL 训练工具）及任何 GPL/AGPL/LGPL 依赖——合规要求，见 `docs/开源协议合规审计报告.md`

新增大文件前自查：`git ls-files -z | xargs -0 du -b | awk '$1>10485760'` 应为空。

## 6. 注意事项

- **不要**在社区仓上直接开发后再合回 main——同步是单向的（GitHub → GitCode）。
- 若社区仓被他人直接提交了新内容：先 `git fetch gitcode`，把对方提交合入 GitHub main（像 2026-08-12 合并 Initial commit 那样），再继续嫁接同步。
- 如果哪天社区仓也需要完整历史：先 `git filter-repo`  purge 掉历史中的 8 个大文件（破坏性，GitHub 需强推、全员重新克隆），再双仓直推。目前无此必要。

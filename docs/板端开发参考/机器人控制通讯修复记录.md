# 机器人控制通讯修复记录

> 时间：2026-08-04  
> 问题：夹爪控制不稳定，SDK 直控校验失败，ROS 话题无响应  
> 修复：清理残留进程 + 启动 servo_manager  
> 状态：已恢复

---

## 1. 问题现象

| 现象 | 表现 |
|---|---|
| SDK 直控失败 | `bus_servo_set_position` 后大量 `校验失败`，位置读不到 |
| ROS 话题无响应 | `/servo_controllers/port_id_1/id_pos_dur` 发布无效果 |
| 位置读取异常 | `bus_servo_read_position` 返回 `None` |
| 串口断开 | `serial.SerialException: RRC serial port is disconnected` |

---

## 2. 根因分析

### 2.1 直接原因：`servo_manager` 未运行

`servo_manager` 是舵机控制的核心节点，负责：
- 订阅 `/servo_controllers/port_id_1/id_pos_dur` 话题
- 调用 `servo_io.set_position()` 下发命令
- 发布 `/servo_controllers/port_id_1/servo_states` 状态反馈

**未运行的后果**：
- ROS 话题发布的夹爪命令无人接收
- 舵机状态反馈中断
- 上层应用以为命令已发，实际未执行

### 2.2 间接原因：残留进程占用资源

`rostopic echo -n 1 /scan`（PID 5797）是我之前健康检查时留下的残留进程，持续占用 ROS 主从资源，可能干扰新节点的注册和通信。

### 2.3 深层原因：SDK 直控与 ROS 节点冲突

当我用 SDK 直控时：
- SDK 自己打开 `/dev/ttyCH343USB0` 串口
- 但 `ros_robot_controller_node`（PID 8290）也在同时读写同一串口
- 两者竞争导致 CRC8 校验失败、数据帧错乱

**结论**：**不要混用 SDK 直控和 ROS 控制**，二选一。

---

## 3. 修复步骤

```bash
# 1. 清理残留进程
kill 5797  # rostopic echo 残留

# 2. 启动 servo_manager（机械臂/舵机管理）
sh /data/robot-host/start-host-arm-4.1.sh

# 3. 验证
ps | grep python  # 应看到 servo_manager 相关进程
rosnode list | grep servo_manager  # 应存在
```

## 6. 注意事项

### 6.1 控制方式选择

| 场景 | 推荐方式 | 禁止 |
|---|---|---|
| 正式比赛/演示 | ROS 话题/Action | SDK 直控 |
| 底层调试/排障 | SDK 直控 | 同时开 ROS 控制 |
| 多机协同 | ROS 网络模式 | 单机直连 |

### 6.2 常见坑

1. **servo_manager 必须启动**：否则舵机命令无人处理。
2. **不要混用控制方式**：SDK 直控和 ROS 控制同时用会串口冲突。
3. **残留进程要清理**：`rostopic echo`、`rosrun` 等测试命令用完即杀。
4. **舵机温度监控**：夹爪长时间工作温度可达 70°C，注意散热。
5. **电压监控**：低于 11V 时舵机可能带不动负载。

### 6.3 紧急情况处理

| 情况 | 操作 |
|---|---|
| 舵机不响应 | 检查 `servo_manager` 是否运行，重启 `start-host-arm-4.1.sh` |
| 串口校验失败 | 检查是否混用 SDK 和 ROS；重启 `ros_robot_controller_node` |
| 底盘不动 | 检查 `chassis_controller` 和 `cmd_vel` 话题 |
| 所有控制失效 | 重启板子，按启动顺序重新拉起服务 |

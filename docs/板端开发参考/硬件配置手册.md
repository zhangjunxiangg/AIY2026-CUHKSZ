# KaihongBoard-3588S-SBC 硬件配置手册

> 调研时间：2026-08-04  
> 调研方式：SSH 直连板端（172.20.10.5:2223）读取 `/proc`、`/sys`、`/dev`  
> 用途：为算法部署与算力规划提供硬件依据

---

## 1. 核心处理单元

### 1.1 CPU（中央处理器）

| 项目 | 规格 | 实测数据 |
|---|---|---|
| 型号 | Rockchip RK3588S | `/proc/device-tree/model` = `RK3588S CoolPi 4B Board` |
| 架构 | ARMv8-A (aarch64) | `platform.machine()` = `aarch64` |
| 核心配置 | 4× Cortex-A55 + 4× Cortex-A76 | 8 核（processor 0-7） |
| 小核频率 | 1.8 GHz | `cpu0-3: 1800000` Hz |
| 大核频率 | 最高 2.256 GHz | `cpu4-6: 2256000` Hz, `cpu7: 408000` Hz（动态调频） |
| 特性 | NEON, AES, SHA1/SHA2, CRC32, atomics, asimd 等 | `Features: fp asimd evtstrm aes pmull sha1 sha2 crc32 atomics fphp asimdhp cpuid asimdrdm lrcpc dcpop asimddp` |

**算力评估**：
- 大核 Cortex-A76 适合高负载计算（SLAM、路径规划、模型推理后处理）
- 小核 Cortex-A55 适合后台服务、传感器数据采集
- 当前负载：`load average: 1.87, 1.82, 2.05`（运行 ROS + Docker + 相机服务时）

### 1.2 GPU（图形处理器）

| 项目 | 规格 | 实测数据 |
|---|---|---|
| 型号 | ARM Mali-G610 MP4 | `/dev/mali0` 存在 |
| 显示接口 | HDMI, DisplayPort | `/sys/class/drm/card0-HDMI-A-1`, `card0-DP-1` |
| 渲染节点 | DRI renderD128/D129 | `/dev/dri/renderD128`, `renderD129` |

**算力评估**：
- Mali-G610 支持 OpenGL ES 3.2 / Vulkan 1.2 / OpenCL 2.0
- 可用于图像预处理、点云渲染、简单并行计算
- **注意**：OpenHarmony 图形栈与标准 Linux 不同，OpenCL 可用性待验证

### 1.3 NPU（神经网络处理器）

| 项目 | 规格 | 实测数据 |
|---|---|---|
| 驱动版本 | RKNPU v0.8.2 | `/sys/kernel/debug/rknpu/version` |
| 核心数 | 3 核 | `NPU load: Core0: 0%, Core1: 0%, Core2: 0%` |
| 当前频率 | 200 MHz | `/sys/kernel/debug/rknpu/freq` = `200000000` Hz |
| 峰值算力 | 约 6 TOPS（RK3588S 标称） | 官方规格书数据 |

**算力评估**：
- 适合部署 INT8/FP16 量化后的 CNN/Transformer 模型
- 典型应用：目标检测（YOLO 系列）、姿态估计、深度估计
- 需使用 RKNN-Toolkit2 转换模型，板端需安装 `rknpu2` Python 包
- **当前状态**：NPU 空闲（0% load），未被占用

## 2. 内存与存储

### 2.1 运行内存（RAM）

| 项目 | 数值 |
|---|---|
| 总容量 | 8 GB（`MemTotal: 8111664 kB` ≈ 7.7 GiB） |
| 可用 | 3.2 GB（`free -h` 显示 `free: 3.2G`） |
| 已用 | 4.5 GB（含 Docker + ROS + 相机服务） |
| Swap | 1.0 GB（未使用） |
| 共享内存 | 165 MB |

**算法部署建议**：
- 8GB 是硬性上限，模型加载 + 图像缓存 + ROS 节点需控制在 6GB 以内
- 大模型（如 LLM、VLM）无法本地全量运行，需裁剪或走云端 API
- 点云处理（PCL）单帧 640×480 点云约 1.2MB，30Hz 下内存压力可控

### 2.2 存储（ROM/eMMC）

| 分区 | 总容量 | 已用 | 可用 | 挂载点 | 用途 |
|---|---|---|---|---|---|
| `/` | 2.8 GB | 2.7 GB | **134 MB** | `mmcblk0p6` | 系统根目录（**96% 已满**） |
| `/data` | 51 GB | 8.8 GB | **43 GB** | `mmcblk0p12` | 用户数据、代码、模型 |
| `/vendor` | 240 MB | 68 MB | 172 MB | `mmcblk0p7` | 厂商驱动 |
| `/sys_prod` | 300 MB | 42 MB | 258 MB | `mmcblk0p8` | 系统产品 |
| `/chip_prod` | 240 MB | 27 MB | 212 MB | `mmcblk0p9` | 芯片产品 |

**算法部署建议**：
- **代码、模型、数据集必须放 `/data`**，根分区只剩 134MB，无法安装新包
- 51GB 可用空间足够存放中型数据集（数千张图像）和多个模型权重
- Docker 镜像存储在 `/data/docker/`，当前已有 `rk3588s-vision` 等镜像

## 5. 算力分配建议

| 任务类型 | 推荐运行位置 | 理由 |
|---|---|---|
| 实时控制（底盘、机械臂） | CPU 小核（A55） | 低延迟、确定性响应 |
| 传感器数据采集 | CPU 小核（A55） | 简单 IO，不占大核 |
| SLAM / 路径规划 | CPU 大核（A76） | 计算密集，需高单核性能 |
| 图像预处理（Resize、Normalize） | GPU / CPU 大核 | 并行加速 |
| 目标检测 / 语义分割 | NPU | 6 TOPS 专用算力，功耗低 |
| 点云处理（PCL） | CPU 大核 | PCL 无 NPU 加速 |
| LLM / VLM 推理 | 云端 API（Kimi/Qwen） | 8GB RAM 无法本地运行 |
| 多模态融合决策 | CPU 大核 + M-Claw | 逻辑判断不占 NPU |

## 6. 已知限制与风险

| 限制 | 影响 | 缓解措施 |
|---|---|---|
| 根分区 `/` 只剩 134MB | 无法 `apt install` 新包 | 代码装 `/data`，或用 Docker 容器隔离 |
| 无本地 LLM 算力 | 大模型必须走网络 API | 提前配好 Kimi/Qwen API KEY；准备离线降级方案 |
| NPU 需 RKNN 转换 | 模型部署多一步转换 | 提前在 PC 上转换好 `.rknn` 模型文件 |
| OpenHarmony 非标准 Linux | 部分 Linux 工具缺失 | 用 `run` 包装器或进入 Docker 容器 |
| GPU OpenCL 未验证 | 无法确认 GPU 通用计算可用 | 优先用 NPU 或 CPU，GPU 只做显示 |

## 7. 快速查询命令

```bash
# CPU 信息
cat /proc/cpuinfo

# 内存
free -h

# 存储
df -h

# NPU 状态
cat /sys/kernel/debug/rknpu/version
cat /sys/kernel/debug/rknpu/load

# 温度
cat /sys/class/thermal/thermal_zone*/temp

# USB 设备
lsusb

# 网络接口
ls /sys/class/net/
```

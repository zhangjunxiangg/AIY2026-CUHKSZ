# 抓取与板端问题修复手册

> 来源：2026-08-05 抓取联调实战记录。每条都是真实踩过的坑，按"现象 → 诊断 → 修复"组织。
> 适用：KaihongBoard-3588S + 驭系列机器人 + grasping pipeline（`/data/local/grasping/`）。

---

## 1. 机械臂关节卡死（J1 实测）

**现象**：发指令后舵机位置不变，如 J1 goal=500 但 pos 恒为 528，err ±28~88，双向指令都无效。

**诊断**：
```bash
cd /data/local/grasping
./arm 1 540    # 不动
./arm 1 440    # 也不动 → 确认卡死（不是回差）
```

**修复**（重启臂栈，亲测有效）：
```bash
ssh -p 2223 root@<板子IP>
sh /data/robot-host/stop-host-arm-4.1.sh
sh /data/robot-host/start-host-arm-4.1.sh
# 应输出 host_arm=RUNNING_HOLDING_CURRENT_POSITION
```
重启后验证：`./arm 1 500` → pos 回到 500±15。

**预防**：避免让臂走到极限位后长时间负重；堆栈异常时舵机命令可能滞留。

## 2. 相机设备号漂移

**现象**：`/dev/video20` 突然不存在，或相机节点报 `cannot open` / `frame capture failed`。

**原因**：icSpring 相机的 video 节点号随 USB 重枚举漂移（实测 video20/21/22 都出现过）。

**修复**：不要写死设备号。用 pipeline 里的自愈脚本：
```bash
sh /data/local/grasping/start_camera.sh
```
它按 `/sys/class/video4linux/*/name` 里的 "icspring" 名字解析设备，逐个验证能出图才算成功。

## 3. WiFi 掉线 / SSH 突然连不上

**现象**：SSH 超时、ping 不通，但机器人看起来正常。

**诊断顺序**：
```bash
ping 172.20.10.5        # WiFi 通不通
hdc list targets        # USB 在不在
```
**注意**：USB 枚举到的板子**不一定是你的板**——现场有多块板，核对序列号（我们的是 `…a523403c00`）。掉线重连后 IP 可能变（.5 ↔ .6），用 `hdc shell ifconfig wlan0` 查当前 IP。

**修复**：WiFi 掉了就等它自动重连（热点机制），或重新插 USB 用 HDC 操作。

## 4. 车不动但里程计在动（假运动）

**现象**：发 `/cmd_vel` 后 `/odom` 数值变化，但车轮实际没转。

**原因**：这台车的 `/odom` 由 `cmd_vel_odom` 节点对**速度指令开环积分**得到，不是轮子编码器反馈。**odom 不能用来判断车是否真的动了。**

**诊断**：绕开底盘控制器，直接发电机指令：
```bash
. /data/robot-host/robot-env.sh
rostopic pub -1 /ros_robot_controller/set_motor ros_robot_controller/MotorsState \
  '{data: [{id: 1, rps: 0.3},{id: 2, rps: 0.3},{id: 3, rps: 0.3},{id: 4, rps: 0.3}]}'
# 1 秒后停止：
rostopic pub -1 /ros_robot_controller/set_motor ros_robot_controller/MotorsState \
  '{data: [{id: 1, rps: 0.0},{id: 2, rps: 0.0},{id: 3, rps: 0.0},{id: 4, rps: 0.0}]}'
```
轮子转 → 底盘控制层问题；不转 → 电机/供电层问题（查电池电压 `/ros_robot_controller/battery`，<11.5V 先充电）。

## 5. "关了但进程还在跑"

**现象**：关了终端/Ctrl+C 后抓取程序还在动。

**原因**：SSH 会话中断不一定杀远程进程；`rostopic pub -1` 等命令也可能残留。

**修复**：用专用停止命令（已带刹车）：
```bash
cd /data/local/grasping
./stop_grasp
```
手动杀进程时**注意 pkill 自杀坑**：`pkill -f grasp.py` 会匹配到执行它的 shell 自身命令行，把 SSH 会话一起杀掉（表现为 ssh 255）。正确写法：
```bash
pkill -f 'python3 gras[p]'    # [p] 让正则匹配不到自己的命令字符串
```

## 6. ROS master 挂掉（Unable to communicate with master）

**现象**：`rostopic list` 报无法连接 master；可能伴随 vision 容器重启。

**修复**（全栈重启，按序）：
```bash
sh /data/robot-host/stop-all-4.1.sh
sh /data/robot-host/start-all-4.1.sh
# 若 start-all 中途报错（如 ttyCH343USB0 暂未枚举），等 3 秒重跑
```

## 7. FK/IK 服务返回全零位姿

**现象**：`/kinematics/get_current_pose` 返回 `success=True, solution=False, pos=[0,0,0]`。

**原因**：当前关节构型超出 FK 模型的有效域。**实测：J4=650 时无解，J4=450 时正常。**

**对策**：抓取 pipeline 已不依赖 FK/IK（J1 旋转对准 + 底盘直进）；如需 IK，把 J4 调回 ≤450 或改抓取构型。pipeline 内已有全零读数自动重试（8 次）。

## 8. 雷达有节点无数据

**现象**：`/scan` 话题存在但 `rostopic hz` 显示 no new messages。

**修复**：

## 9. 换板恢复 SOP

新板/重刷板后恢复全部环境（代码均在本地仓库有备份）：

```bash
# 1. 装 SSH 公钥（HDC 连接下）
KEY=$(cat ~/.ssh/id_ed25519.pub)
hdc shell "mkdir -p /data/robot-host/mclaw-sshd && echo '$KEY' >> /data/robot-host/mclaw-sshd/authorized_keys && echo '$KEY' >> /var/empty/mclaw_authorized_keys"

# 2. 部署代码（本地仓库根目录执行）
ssh -p 2223 root@<新板IP> "mkdir -p /data/local/perception"
scp -P 2223 gripper_camera_node.py root@<新板IP>:/data/local/perception/
BOARD=root@<新板IP> bash src/grasping/sync.sh

# 3. 启动栈 + 相机
ssh -p 2223 root@<新板IP> "sh /data/robot-host/start-all-4.1.sh; sh /data/local/grasping/start_camera.sh"

# 4. 验证
bash scripts/check-control-ready.sh
```

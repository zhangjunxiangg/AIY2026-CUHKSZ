## 阶段一：赛前准备期（7/28 – 8/3）—— "把所有 plan 做齐"

这一阶段还没有摸到硬件，全部工作围绕**信息收集、环境搭建、团队组织、方向调研**展开。主导会话：`AIY 黑客松实战项目指引`（115 prompts）及其 Fork（210 prompts，两会话 8/4 前内容重叠）。

### 7/28：项目启动 + 文档化工作方式确立

- 17:31 第一条 prompt：用 doc2x 把官方《新手快速入门手册.pdf》转成 MD——**从第一天起就确立了"一切材料转 MD、一切结论落文档"的工作方式**，贯穿整个项目。
- 当天完成：上手硬件前的环境准备调研（多源 audit 3 遍）、文件夹 artifacts 整理、踩坑与知识库文档。
- 19:50 关键决策：明确 8/3–8/6 参加 M-Robots 黑客松，"尽可能将所有 plan 做齐"，用 `/octie-research` 建立整体任务图谱（octie 任务图从此成为项目管理的骨架）。

### 7/29–7/30：团队组建 + 工具链自建

- 确认开发系统问题（Windows/Linux 是否都需要）。
- 7/30：5 人组队的分工疑问（"会不会有人负责 dora、有人负责 ROS"）→ 产出《项目启动全员必备知识文档》。

- 列出给赛事指导老师的 **Top 10 技术问题**；新一批官方资料（`AIY文件/`）全部 doc2x 转 MD，更新比赛认知。
- **8/1 关键信息（导师回复）**：系统镜像、ROS 包、Python 环境已预制在板子里，**不需要自己烧录**；板子出问题有备用板；代码做好备份。→ 团队方向收敛为"专注上层运控和决策"。
- Windows 开发机环境全部安装到 `D:\AIY-Hackathon`（不入 C 盘），human-in-the-loop 方式逐项确认；产出工具使用简介文档、团队学习待办文档。

### 8/1 晚：产品方向的第一次深思（重要转变点 ①）

- 01:30（8/2 凌晨）两条连续 prompt 是**产品方向的源头思考**：
  - "驭系列移动底盘+夹爪，在 M-Claw 和软总线下能执行什么任务？感觉做出来的都比较同质化，**场景的定义和理解显得非常重要**" → 要求做市场调查，合理化几个大的发展方向。

### 8/2：分工落定 + 0802 会议 + Git 仓库建立

## 阶段二：8/4 白天 —— 板子到手，从"连不上"到"无线控制"（里程碑爆发日 ①）

8/4 是**整个项目的第一个突飞猛进日**。一天之内完成了：板子点亮 → HDC 连接排障 → SSH 无线通路 → 底层夹爪直控 → 健康检查脚本体系 → 产品任务拆解。主要记录在 Fork 会话 #67–#181 与主线会话 #67–#115。

### 8/4 下午（14:19–17:47）：板子点亮与 HDC 拉锯战

- 14:19 拿到开发板，开始连接：网线 → USB Type-C → 通电，屏幕显示 "kaihongos 未激活"（导师答复：时间不对导致，不影响使用）。
- ROS 1 运行时确认可用；舵机 3 无数据（导师：角度超限，掰直即可）——**第一次体会到"先问导师"比瞎猜快**。
- 开始 dry-run 采集传感器数据格式（不控制运动，只读数据），回填《传感器数据规格手册》。
- **HDC 突然断连**（`hdc list targets` 返回 Empty）：从 16:32 排查到 17:47+，查命令历史、zadig 看 USB 驱动、怀疑驱动未加载——这是当天的第一个大坑，最终定位到**板端 HDC 模式需要切换**（先无线连上板子，在板子上设置后才恢复有线连接）。排查过程全部记入踩坑手册。

### 8/4 下午（15:31–16:44）：网络配置与团队协作通路

- 网络方案反复尝试：网线插路由器 LAN、静态 IP 直连、换 WiFi、手机热点内网。
- 提出**团队协作的网络问题**：只有一块板子、一个人连着电脑，其余 4 人怎么接入？→ 调研 tailscale 局域网方案（单独小会话，后演化为 SSH 密钥分发方案）。

### 8/4 晚（17:33–18:29）：三大突破接连落地（突飞猛进点 ①）

1. **SSH 通路打通（里程碑）**：按《kaihong-ST-04 SSH 连接与配置操作手册》在板端开 SSH；用自己电脑的公钥配置密钥认证（`ssh -p 2223 root@<板端内网 IP>`）。18:16 确认："**现在可以直接把 USB 拔了，车就可以在地上测试了**"——从被线缆拴住到无线自由控制，是当天最重要的解放。队友的 SSH 公钥也一并分发，多人协作通路打开。
2. **健康检查体系**：写完 `scripts/healthcheck.sh` 一次性验证全链路（HDC/传感器/线路），commit & push；legacy 脚本归入 `_trash/`。
3. **密钥安全**：push 前 audit 密钥泄漏，SSH 密钥、证书、captures 全部加入 .gitignore。

### 8/4 晚（18:29–21:07）：摸清家底 + 夹爪底层直控（突飞猛进点 ②）

- 读取板端硬件配置（RK3588S：CPU/GPU/NPU/内存）→《板端硬件配置手册》；评估能跑论文里的哪些算法 →《算法部署可行性评估（RK3588S vs LG-grasping/RoboBridge）》。
- 队友在板端产出夹爪只读报告：**发现夹爪 ID10 底层 position_limit=[0,700]，而 Skill 文档里写的软件范围是 250..800——文档与硬件不符，超过 700 的值一律不能用**；且系统没有已验证的"回零"动作。
- **直接绕过上层代码，SSH 直发底层 SDK 命令控制夹爪**：先误合后开（方向搞反）、总线繁忙（查进程、修复串口占用）、raw topic 设 position 300/400 成功。**这是全项目第一次"代码直接驱动物理世界"**，当晚立刻沉淀：《机器人控制通讯修复记录》+ `scripts/check-control-ready.sh`（控制前必跑）+ 控制前检查清单写进 README。
- 三个脚本推送到板端，板端 README 同步；配置 SSH 开机自启（端口 22+2223 双服务）。

### 8/4 深夜（21:40 – 8/5 00:35）：把板子带回家 + 规则边界 + 产品任务拆解（重要转变点 ②）

- 板子带回家继续调：VNC 黑屏（放弃面板路线），改用 HDC shell 的 `sta_test` 菜单配 WiFi，连上手机热点。
- 盘点赛事硬件与规则边界：双板架构（机器车板 + Gemini335 辅助相机备用板）、算力边界、通讯方式 →《赛事资源与规则边界手册》；clone 软总线源码分析 →《分布式软总线源码分析》。
- **8/5 00:34，产品方向定型的一条长 prompt**：完整拆解最终要呈现的任务流——
  - 任务入口（Trigger）= M-Claw 指令（M-Claw 本身的缺陷要向官方提 issue）；
  - **绝对坐标定位两个方案：① 车载深度+RGB 自标定；② Gemini335 深度相机放场边俯拍全场，外部定位机器人**（后来方案②成为主力路线）；
  - 任务拆解：确定目标位置 → 避障到达 → 识别物体/符号 → 抓取/巡检 → 回归出发点；
  - 算法盘点：每个算法的频率、算力需求、端侧/外部部署可能性。
  → 全部写入《比赛执行细节手册 v1.0》，audit 3 遍以上。**这份手册是产品方向的定稿：M-Claw 做大脑、Gemini335 做上帝视角、底盘+夹爪做执行。**

### 8/4 小结

- **一天解决的问题**：HDC 断连根因（板端模式）、SSH 无线控制、夹爪底层直控、总线繁忙、文档范围错误（700 vs 800）、多人协作网络。

- 同一天还完成了队长卡片初稿（扫描全部会话 prompt + 文档，以队长口吻撰写），并纠正"队长是张宇辰"对齐所有文档。

## 阶段三：8/5 比赛日主开发日 —— 三线并进，抓取端到端打通（里程碑爆发日 ②）

8/5 是开发密度最高的一天，**三条技术线并行推进**：抓取线（夹爪+像素伺服）、底盘线（队友代码接手+遥操）、感知线（YOLO 训练管线）。三个会话（机械臂抓取标定控制流程及其 Fork、机器人避障算法、机器底座运动控制）共享同一段 morning context，午后分头展开。

### 8/5 上午（09:53–11:30）：状态同步 + 机械臂直控扩展

- 两个健康检查脚本已入库并同步到板端，SSH 直连跑通；两端（PC/板子）代码同步机制确立。
- 从夹爪扩展到整条机械臂：SSH 直控 3 号舵机（方向又反了——**舵机方向先验知识缺失是反复出现的坑**）；列出全部关节角度与运动范围；产出《夹爪 CLI 控制手册》并 commit。
- 查板端有无 URDF / 逆解算法 → 有，逆解用法同步进文档。
- 关键认知对齐（11:22）："系统现在能做到什么？手眼标定是什么？抓取任务应该先做什么再做什么？"——为下午的抓取方案选型做铺垫。

### 8/5 上午（11:32）：产品/技术方向的关键决策（重要转变点 ③）

一条长 prompt 定下抓取技术路线，这是全项目最重要的技术决策之一：

- **相机选型**：抓取不用 Astra 车顶相机，**用机械臂末端夹爪上的相机（icSpring）**——眼在手上（eye-in-hand）。
- **方案 A 约束**：只用夹爪相机信息、不移动底盘（后来放开），只控制机械臂和夹爪。
- **任务定义**：现场摆红/黄/绿三个圆柱体，用**质心检测 + 像素伺服（pixel servoing）**夹取指定颜色。
- **开发方法论**：强制 **gated success pipeline**——每一步先验证再推进（01_camera_ready → 02_detect_centroid → 03_arm_state → 04_jog_probe → 05_align → 06_descend → 07_grasp → 08_full_run），板端独立文件夹 `/data/local/grasping/` 运维，本地同名文件夹同步。
- **成功标准**：输入颜色+形状 → 全自动抓起。`set /goal until finish`——这个 goal 一直跑到当天傍晚。

### 8/5 中午（12:00–14:00）：标定与安全边界的人肉攻关

- **无 HOME 位问题**：夹爪没有初始化标定位 → 用户肉眼标定给出 HOME=(500, 210, 150, 450, 500, 300)；过程中发现"第 5 个关节"（夹爪朝向旋转电机）的存在。
- 安全守卫上线：`util_board.py` 里舵机跳变 >120 tick 直接 `SafetyError` 拒绝执行——**安全约束是用户全程反复强调的红线**。
- 为用户造调试工具：`./arm <joint> <pos> <duration>` CLI（用户自己手测关节）、`./car <dir> <dist>` 底盘 CLI。
- **抓取策略的用户设计**（14:22，体现队长对系统的理解）：关节 2/3/4/5 固定在肉眼标定位 → 转 Joint 1 让物体质心对齐中线 → 底盘前进闭合距离 → 夹取。担心旋转碰物 → 后续改为"底盘旋转对准"替代 Joint 1 旋转，并给出先验："turn + 是左转，- 是右转"。

### 8/5 下午（14:49–16:29）：像素伺服抓取端到端打通（突飞猛进点 ③）

一连串高频迭代（14:49–16:29，约 100 分钟内的 20+ 条 prompt 全是实测反馈）：

- 夹爪放下前没张开 → 修；像素对齐后还差几厘米 → +4cm、+5cm 逐步逼出补偿量；
- "不要摇头"——相机左右扫描改为**一次性质心定向**；
- **"夹住了但没判断出已夹住"** → 用夹爪状态反馈做夹持判定（状态不再变化=夹住），并把"一次标定+前进补偿"固化为通用夹取顺序；
- 16:04 `./grab red` 首次全管线跑起：GATE PASS shape_supported，GATE FAIL home_reached（J1 停在 528 而非 500）→ 重启臂控进程、问题修复文档入库；

### 被解决的核心问题清单（按领域）

- **连接/基建**：HDC 断连根因（板端 HDC 模式切换）、SSH 密钥认证（持久化+运行时双写）、开机自启双 sshd（22+2223）、重启后服务不全（bringup 恢复脚本）、多人协作网络（SSH 公钥分发，tailscale 方案被替代）。
- **硬件真相**：夹爪 position_limit=[0,700] 戳破文档 250..800 的错误；舵机方向无先验需逐一探测；舵机 3 角度超限导致无数据；雷达 USB 重新枚举设备名漂移；**双相机 USB 带宽竞争（最终大 BOSS）**。

- **流程/协作**："一切材料转 MD、一切结论落文档"；小步 commit 救回滚；隐私/密钥 audit 成习惯（也有漏网：API key 曾明文贴进 prompt）；删除事故催生出"只移动不删除"铁律。

## 3. 全员必备（5 个人都必须会，不分角色）

黑客松现场节奏极快，不存在"这事只有某某会"的容错空间。以下每人都要亲手做过：

### 3.1 会部署（每人练 ≥2 遍）

```bash
# 开发循环六步：写码 → 推板 → 手动跑 → 挂 dataflow → 看日志 → 调试
hdc list targets                          # 确认板子连接
hdc file send my_node.py /data/local/robot/   # 推代码
hdc shell                                 # 进板子
mount -o remount,rw /                     # 根分区可写
run python3 /data/local/robot/my_node.py  # 手动跑（排障第一步永远先手动跑）
run dora up && run dora start /data/local/robot/dataflow.yml   # 挂数据流
```

- 记住：**机器人相关命令几乎都要 `run` 前缀**；节点代码放 `/data/local/robot/`
- 板上 pip 只能装纯 Python 包；日志字符串用英文（中文乱码）

### 3.2 会跑 Dora 与 ROS1 的最小 Demo

- Dora：节点写法（`from dora import Node`、`send_output`、timer 输入）、`dora up/start/list/logs/stop`
- ROS1：`run roscore` + `rospy` 节点；Dora 可以把 ROS 节点当进程统一管理
- 每人赛前把三个官方样例各跑一遍（Dora 定时器、Dora 传感器+滤波、ROS1 talker/listener）

### 3.3 会查日志排障（现场 80% 时间在 debug）

- `hilog -b d -p off | grep 关键字`（**另开干净 shell**，别在 source 过 ros2_env 的 shell 里跑）
- 节点起不来三板斧：①手动 `run python3` 看报错 ②`run ldd` 查缺库 ③查 dataflow.yml 语法
- 崩了看 `/data/log/faultlog/faultlogger/`；Dora 会自动重启崩溃节点，先 `dora stop` 再查
- HDC 连不上：`hdc kill && hdc start`

### 3.4 会 Git 协作

- 约定：每人一个分支，合并到 main 前口头同步；`dataflow.yml` 和共享消息格式文件**只允许当值集成负责人改**（避免冲突）
- 节点间消息格式（话题名/字段/单位）写在 `接口约定.md`，改了要喊一声

### 3.5 读过三份文档

《踩坑与参考库》《赛题宣讲转录》《赛事细则》——至少读一遍，知道什么东西在哪查。

## 4. 五人分工（按"系统分层"分，不按"Dora 一人 ROS 一人"分）

**为什么不按中间件分**：Dora 是骨架、ROS1 是应用环境，两者是同一个 pipeline 的不同层，每个节点的作者都要同时懂一点。按中间件切会把一条数据流切成两半，接口扯皮。按**系统分层 + 角色**切，每个人对自己那层端到端负责：

| 角色 | 负责 | 赛前深入方向 | 现场产出 |
|------|------|-------------|---------|
| **A. 队长 / 集成与答辩** | 场景定义、dataflow 总架构、接口约定、演示脚本、文档 PPT | 评分标准研究、dataflow.yml 编排、init.cfg 自启（演示上电即跑） | 场景故事、系统架构图、演示视频、答辩 PPT（15+10+10 分的直接责任者） |
| **B. 板务与部署** | 两块开发板的环境：烧录、配网、Docker 确认、运行时部署、自启服务、现场救援 | 烧录全流程、sta_test 配网、hdc 网络连接、自启 cfg、应急 checklist | 两块随时可用的板子、现场工具包、故障 5 分钟恢复能力 |
| **C. 感知算法** | 深度相机/雷达数据接入、目标检测识别、点位/二维码识别 | Orbbec 相机与 Astra Pro 数据格式、ROS1 图像话题、轻量视觉算法（颜色/标签/二维码检测优先，别押 NPU） | 感知节点：输入图像/点云，输出目标位置与类别 |
| **D. 机器人控制** | "驭"机器人操控源码解读、底盘移动、机械臂抓取、导航到点位 | **板端操控源码**（拿到板第一时间啃）、麦克纳姆轮运动学、5 自由度机械臂控制 | 控制节点：接收目标位置 → 移动/抓取/投放动作 |
| **E. M-Claw 与协同** | M-Claw 智能体接入、任务规划链路、两块板+机器人的软总线协同 | M-Claw 授权与 API（赛前确认）、软总线/M-DDS 通信、自然语言指令→任务拆解演示 | M-Claw 任务理解节点 + 多设备状态同步（25 分维度直接责任者） |

**协作接口**：C 输出"目标位置"给 D；E 输出"任务指令"给 C/D；B 保障环境；A 定义消息格式并串联成完整演示。

**备份原则**：每个角色有副手（A↔E、B↔D、C 独立），任何人累了/卡了有人能接。

## 8. 常见疑问 FAQ（队内）

**Q：是不是一人负责 Dora、一人负责 ROS？**
不是。Dora 是数据流骨架、ROS1 是应用开发环境，每个节点作者两个都要会基础。分工按系统层（感知/控制/协同/部署/集成），不按中间件。

**Q：ROS1 还是 ROS2？**
官方 PPT 写的是 **ROS1**（noetic）作为机器人应用开发环境，以 ROS1 为主线准备；ROS2 (Jazzy) 也有文档但属备选。

**Q：要不要学 M-Claw？**
要，但它没有公开文档——E 角色负责通过社区/主办方搞清楚，搞清楚前先用普通 Dora 节点模拟任务规划链路，保证没有 M-Claw 演示也能跑。

**Q：要不要学 Docker？**
不用深入，知道"板上可能有容器化运行环境"即可，现场问主办方怎么用最省事。

**Q：AI/模型推理怎么办？**
RKNPU 官方文档未发布，不要把核心功能押在 NPU 上。视觉检测优先用轻量传统方法（颜色阈值、二维码识别、模板匹配），板上 Python 直接跑得动。
